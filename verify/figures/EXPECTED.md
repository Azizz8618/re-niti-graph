# Ожидаемые признаки сложных фигур графопостроителя

Набор проверяет, что тракт

```
FOREX MOVE -> /GFAFTR/ -> PLOT -> /PDEVXY/ -> PDEV -> ЭК 1210/1211 ->
plot.dat -> coords-декодер -> benson.out -> plotter.cpp -> benson.svg
```

остаётся рабочим при большом числе различных координат и длинных программах.
`PLOTSTUB.FTN` передаёт адрес кадра аргументом (`CALL PDEV(FRAME(1))`), поэтому
захардкоженного адреса `/PDEVXY/` больше нет и длина дека не ограничена.

Координаты в деках — целые числа `.0` в шагах 0.1 мм. Диапазон порта:
`X = 0..5000`, `Y = 0..7500`. Все точки всех шести фигур лежат внутри
`X = 50..950`, `Y = 88..833`, то есть далеко от границ.

## Что генерирует деки

`gen_decks.py` считает координаты заранее (чистая математика, `math`),
проверяет диапазон и отсутствие совпадающих соседних точек и записывает в
каждую `.b6` deck **явные** строки

```
      CALL MOVE(500.0,100.0)
      CALL PLOT()
```

Ни циклов, ни арифметики в Fortran-тексте нет. Там же получается
`expected.tsv` с машиночитаемым контрактом для `run.sh`:
`name, points, maxX, maxY, expW, expH, description`.

## Почему SVG не «идеальная» геометрия

1. **Manhattan-движение.** `du_decode_stream_coords()` в `dispak/extra.c`
   эмитирует сначала все шаги `±X`, затем все шаги `±Y`. Наклонная сторона
   превращается в L-образный штрих: горизонталь, вертикаль. Кривая — в
   лестницу из таких штрихов.
2. **Первый штрих из начала координат.** Начальная позиция пера `(0,0)`,
   перо поднято; первый `PLOT` проводит линию от `(0,0)` к первой точке.
   Поэтому число `<path>` равно числу кадров (`PLOT`), а не числу отрезков
   между точками: N кадров дают N элементов `<path>`.
3. **Квантование `INT`.** `PLOT()` берёт `INT` от REAL-координаты, поэтому
   дробная часть отбрасывается. Стороны многоугольника и синусоида
   аппроксимируются ступенчато; это ожидаемо, а не ошибка.
4. **Перевёрнутая ось Y.** `Y_svg = maxY - y`, поэтому звезда «стоит вниз
   вершиной» в SVG хотя в координатах БЭСМ-6 вершина находится вверху.
5. **Схлопывание коллинеарных точек.** `plotter.cpp` убирает точки, лежащие
   на одной прямой (`is_collinear()`), поэтому в `<path>` может быть 2 или 3
   пары координат: 3 означают один L-излом.
6. **Размер растра.** `width = max(X) + 2`, `height = max(Y) + 1`, где
  максимум берётся по всем шагам БЕНСОНа. Шаги лежат внутри bbox точек, поэтому
   достаточно максимума по координатам `MOVE`. Раннер допускает отклонение
   ±2, чтобы не ломаться на возможной правке оклада.

Код в `benson.out` — шесть команд `[аналог NASA, БЕНСОН-501]`:
`6501 (+Y)`, `6502 (+X)`, `6504 (-Y)`, `6511 (UP)`, `6512 (DOWN)`,
`6514 (-X)`. Фактический бэкенд пишет 4-значные коды; раннер принимает и
4-значную, и 5-значную форму с ведущим нулём (`065xx`), как она описана в
`docs/BENSON-COMMAND-FORMAT.md`. Каждая строка обязана заканчиваться пометкой
аналога.

## Что считается прохождением

По две прогонки на деку (r1, r2). Обе должны дать:

- `NITI: summary` и `КОНЕЦ ЗАДАЧИ`, ни одного `ОШ` / `ERR` / `ОТСУТСТВУЕТ`;
- непустые `plot.dat`, `benson.out`, `benson.svg`;
- `benson.out`: каждая непустая строка — одна из шести команд 065xx с
  пометкой `[аналог NASA, БЕНСОН-501]`;
- `benson.svg`: начинается с `<?xml`, содержит `<svg`, ровно ожидаемое число
  `<path>`, `width`/`height` в пределах ожидаемого bbox ±2;
- SHA256 `plot.dat`, `benson.out` и `benson.svg` идентичны между r1 и r2.

Критерий набора: минимум 6 PASS. Адрес `/PDEVXY/` в логах не проверяется —
он передаётся аргументом и зависит от длины пула констант. Отсутствие
артефактов означает FAIL с причиной, а не выдуманные значения.
