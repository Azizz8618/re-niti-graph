# Запуск РОДНОЙ библиотеки ГРАФОР-СУД (библиотека 22)

Демонстрация того, что нативный DMS-код библиотеки 22 с тома 2048/2348
реально выполняется в `dispak` и выдаёт кадр графопостроителя.

## Идея

Родные модули библиотеки 22 ссылаются на точки входа **вторичного каталога**
(зона `0o1163`): `PLOT`, `MOVE`, `RDB`, `ENDPG`, `PAGE`. Это не отдельные
модули основного каталога, поэтому фортранный линкер их не находил
(`ОТСУТСТВУЕТ PAGE/MOVE/RDB/ENDPG`). Библиотека 12 в зонах 1170-1177 на
этих дисках оказалась `*JLIB:К71`, а не GRAFOR-BATR.

Решение: собрать маленькую МАДЛЕН-прослойку с этими пятью точками входа
в PERSO-библиотеку зоны `0o2700`. `PLOT` выдаёт `ЭК 1210` (выбор схемы
НИТИ) и `ЭК 1211` (кадр 64 слова), остальные точки просто возвращаются
через `13,UJ,`. Вычисления при этом делает **родной код** библиотеки 22.

## Файлы

- `SHIM.mad` — МАДЛЕН-исходник прослойки (пять `,NAME,` секций).
- `shim.b6` — дека сборки прослойки в PERSO `0o2700` (обязательна строка
  `*perso:602300` перед `*assem`, иначе запись уходит в зону `0o3700`).
- `native-final.b6` — дека с нативным вызовом `MOVE1(N,X,Y)` и `ARCIA(0.0)`.
- `plot.dat` — эталонный кадр, полученный родной библиотекой.

## Воспроизведение

```
W=/var/tmp/native-graf-run
mkdir -p "$W/disks"
cp /home/azizz/Yandex.Disk/dispak/build/dispak/2048 "$W/disks/"
cp /home/azizz/Yandex.Disk/dispak/build/dispak/2053 "$W/disks/"
cp /home/azizz/Yandex.Disk/dispak/build/dispak/2099 "$W/disks/"
cp /usr/local/share/besm6/2148 "$W/disks/"
cp /usr/local/share/besm6/2348 "$W/disks/2348"

# 1) собрать прослойку в зону 0o2700
cd "$W"
BESM6_PATH="$W/disks" /home/azizz/Yandex.Disk/dispak/build/dispak/dispak -l shim.b6

# 2) прогнать нативную программу
BESM6_PATH="$W/disks" /home/azizz/Yandex.Disk/dispak/build/dispak/dispak -l native-final.b6
```

Не использовать `/tmp` — там кончилось место; `/var/tmp` лежит на диске.

## Результат (проверено дважды, воспроизводимо)

Лог:

```
NITI: scheme 1210 selected
NITI: summary schemes=1 frames=1 words=64 active=1 scheme=1210
 КОНЕЦ ЗАДАЧИ
```

`ОТСУТСТВУЕТ`, `E_UNIMP`, `ERR nnnn`, `БЫЛИ OШИБKИ` — отсутствуют.

| Источник | Кадров | Размер plot.dat | SHA256 |
|---|---:|---:|---|
| родная библиотека 22 + прослойка `0o2700` | 1 | 1600 | `15450e0b433bfbc2c2cac11d2528e7a9626f444a0d60b2290c6b325ddff25b2d` |
| наш Фортран-порт, тест C1-line | 2 | 3200 | `7b362ec4efd7…` |

Кадры отличаются, потому что это разные программы: родной `MOVE1` берёт
координаты из общих блоков ГРАФОР (`*GFBFTR*` и др.), а тест C1 порта задаёт
точки явно `MOVE(10,10)` и `MOVE(110,110)`. Главный результат — сам факт,
что нативный DMS-код библиотеки 22 выполнился и выдал кадр через ЭК 1210/1211.

## Оговорки

- Нативный `ARCIA` ожидает **один** аргумент; при пяти печатает
  «НЕ ТЕ ПАРАМЕТРЫ». С одним аргументом линкуется, но точек не эмитирует
  из-за неинициализированных общих блоков.
- Повторный вызов `PLOT` в одной задаче даёт «ВЫВОД ЗАПРЕЩЕН», поэтому
  финальный прогон создаёт ровно один кадр.
- ЭК 1205 (`ГРАФИК`) не пишет `plot.dat`: по `trubka.be:490-507` это сигнал
  ожидания и печать `ВК.Г` на терминал. Имитация 1200-1207 в `dispak`
  добавлялась для снятия `E_UNIMP`, а не для генерации кадров.
- Полная имитация `ФИЗОБМ`/КУС с битом 27 (вариант B1) не реализована;
  кадр идёт через расширенный обработчик 1211.
- Попытка заменить буфер нулей координатами из `*GFAFTR*` описана в
  [`REPORT.md`](REPORT.md). Результат: **BLOCKED**. Найдены абсолютные адреса
  COMMON из кросс-ссылки, формат чисел и причина пустого `*GFAFTR*`
  (`PLOT` вызывается до записи в COMMON, а заглушка `RDB` не выдаёт
  аргументы). Стабильного преобразования REAL в шаги внутри МАДЛЕН нет;
  предложен минимальный режим `coords-real` в dispak, не внесённый в код.
- Разделы 7-8 `REPORT.md`: извлечение трёх аргументов `PLOT` и попытка
  исправить `RDB` (адреса `0o1562/0o1564`, возвращаемые значения, почему
  кадр не совпал с портом). Итог тот же: **BLOCKED**, нужна правка `RDB`.
- Раздел 9 `REPORT.md`: `RDB` - каталожная ссылка на точку входа драйвера
  ГРАФОР без тела на доступных томах; формат её буфера не описан ни в
  дизассемблерах, ни в OCR-книгах, ни в `re-dispak/`. Любая заглушка пока
  была бы угадыванием, поэтому ни одна в рабочие файлы не внесена.
