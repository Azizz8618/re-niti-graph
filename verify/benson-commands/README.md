## 1. Что именно проверяется

NASA TM-76182 (таблица 2, стр. 6-7 PDF) описывает графопостроитель
`BENSON-FRANCE` модели 501, подключённый к Электронике-1001. Это не протокол
НИТИ и не протокол БЭСМ-6. В советской части НИТИ/ДУДКИ формат команд на
проводе не найден. Поэтому все коды ниже и шаг 0.1 мм это OSINT-модель,
перенесённая на dispak, а не доказанный исторический протокол.

Физическая модель по NASA: пять шин управления, шаговые двигатели, шаг
0.1 мм, импульс `+5 В` на шине равен одному шагу. Пять шин дают шесть команд,
потому что `Pen Control` кодирует два состояния пера (`UP` и `DOWN`).

| Команда | Физическая шина | Код (восьм.) | Начало строки в `benson.out` |
|---|---|---:|---|
| `+X` | `+X` | `6502` | `6502 +X` |
| `-X` | `-X` | `6514` | `6514 -X` |
| `+Y` | `+Y` | `6501` | `6501 +Y` |
| `-Y` | `-Y` | `6504` | `6504 -Y` |
| `UP`, перо вверх | `Pen Control` | `6511` | `6511 UP` |
| `DOWN`, перо вниз | `Pen Control` | `6512` | `6512 DOWN` |

В восьмеричной нотации тот же код иногда пишут с ведущим нулём,
`06502`, `06511`. Раннер принимает обе формы.

Коды сверены по изображению страницы 7 PDF (`docs/BENSON-PROTOCOL.md`).
Текстовое распознавание `docs/reference/NASA-TM-76182.txt` таблицу 2 исказило
(`65U2`, `6314`, `65A`, `b5II`), поэтому при расхождении верен PDF.

## 2. Формат `benson.out` (контракт)

`benson.out` это текстовый файл, одна команда на строку. Фактический формат
строки, наблюдаемый после сборки бэкенда:

```
6511 UP X=00000 Y=00002 [аналог NASA, БЕНСОН-501]
6502 +X X=00001 Y=00002 [аналог NASA, БЕНСОН-501]
6504 -Y X=00002 Y=00001 [аналог NASA, БЕНСОН-501]
```

То есть: восьмеричный код NASA, пробел, мнемоника команды, координаты
перо в шагах 0.1 мм и обязательная пометка аналога. Код может быть записан
и с ведущим нулём (`06511`, `06502`), раннер допускает оба вида.

Правила, которые проверяет раннер:

1. Файл существует и непуст.
2. Есть строка с кодом `06511`/`6511` (`UP`) и строка с кодом
   `06502`/`6502` (`+X`).
3. Есть пометка `[аналог NASA` (достаточно подстроки; полная форма
   `[аналог NASA, БЕНСОН-501]` принимается).
4. Нет числовых значений вне множества шести кодов таблицы выше, если
   проверка делается вручную (раннер этот пункт не проверяет).

`benson.svg` это векторный результат рендера того же потока команд через
проверенный бэкенд `plotter.cpp`. Раннер требует только существования и
непустоты файла. Признаки корректного SVG описаны в
[`EXPECTED.md`](EXPECTED.md).

Главная гарантия: `plot.dat` не меняется. Он по-прежнему пишется функцией
`niti_plot_write()` до нового слоя, его SHA для деки C1-line зафиксирован
и проверяется в обоих прогонах.

## 3. Запуск

Базовый запуск из корня репозитория:

```
./verify/benson-commands/run.sh
```

С явными путями и сохранением временных файлов:

```
DISPAK_BIN=/home/azizz/Yandex.Disk/dispak/build/dispak/dispak \
NITI_2348=/home/azizz/Yandex.Disk/re-niti-graph/fortran/verify/2348-niti.img \
KEEP_WORK=1 \
./verify/benson-commands/run.sh
```

Переменные окружения:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `DISPAK_BIN` | путь к бинарнику dispak с новым бэкендом | `/home/azizz/Yandex.Disk/dispak/build/dispak/dispak` |
| `NITI_2348` | рабочий диск 2348 с библиотекой PERSO | `$ROOT/fortran/verify/2348-niti.img` |
| `TMPDIR` | основа для временного каталога | `/tmp/.private/azizz/opencode` |
| `KEEP_WORK` | если непусто, временный каталог не удаляется | unset |
| `REF2148` | системный диск 2148 | `/usr/local/share/besm6/2148` |
| `TIMEOUT` | таймаут одного прогона, секунды | `240` |
| `VERBOSE` | если непусто, печатать подробности | unset |

Раннер копирует диски 2048, 2053, 2099, 2148 и 2348 во временный каталог,
затем дважды прогоняет одну и ту же деку `verify/C1-line.b6` с переменными
`BESM6_DUDKA_PLOT=benson`, `BESM6_DUDKA_TEST=1` и
`BESM6_DUBNA_PLOT_KEEP=1`. `ctest` не запускается намеренно, его запускает
lead.

## 4. Критерии прохождения

Для каждого из двух прогонов:

1. В логе есть строка `NITI: summary schemes=2 frames=2 words=128 active=1 scheme=1210`.
2. SHA `plot.dat` равен `181ed477d5a97392d092978cccefa9b56f7434d56d1f373952f8325e6dd585ea`.
3. Созданы непустые `benson.out` и `benson.svg`.
4. В `benson.out` найдены коды `06511`/`6511` и `06502`/`6502`.
5. Найдена пометка `[аналог NASA` в `benson.out` или в логе прогона.

Дополнительно между прогоном 1 и прогоном 2 сравниваются SHA файлов
`plot.dat`, `benson.out` и `benson.svg`. Все три должны совпасть.

Итог раннера: `Summary: 1 PASS, 0 FAIL (of 1 cases)`. Любое несовпадение
это FAIL с указанием конкретной причины. Если бэкенд не собран, раннер
печатает FAIL с кодом выхода 3.

## 5. Оговорка про аналог

Коды `6501/6502/6504/6511/6512/6514`, пять шин, шаг 0.1 мм и пределы
поля 50 x 75 см пришли из отчёта NASA про Электронику-1001. Это современный
аналог советского интерфейса, а не рекомендация НИТИ и не описание шин
БЭСМ-6. Каждая выдача команды должна помечаться `[аналог NASA,
БЕНСОН-501]`, см. `docs/BENSON-COMMAND-FORMAT.md`, раздел "доказано / аналог /
не найдено". Нельзя называть этот поток "протоколом НИТИ", "доказанным
протоколом БЕНСОНа" или выдавать его за эталон Дубны.

Рендер через `plotter.cpp` проверен эталонами Дубны как приёмник байтов,
но это не доказывает происхождение самих команд. Слово `proven` относится
к коду рендера, а не к протоколу БЕНСОНа/НИТИ.
