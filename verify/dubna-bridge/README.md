## 1. Архитектура моста

Идея: не переписывать графику, а подключить проверенный бэкенд из эмулятора
Дубны как дополнительную программу графического вывода. «Проверенный»
означает: у него есть собственные эталонные тесты в репозитории `besm6/dubna`.
Это не означает, что его протокол совпадает с протоколом НИТИ.

Путь данных в dispak:

```
CALL PAGE / MOVE / PLOT  (Фортран, PERSO 4.12 на диске 2348)
        |
        v
Э50 01210 (выбор схемы), Э50 01211 (запись кадра)
        |
        v
niti_plot_write()  ->  plot.dat: 64 слова на кадр,
                       8 восьмеричных 6-битных чисел на строку,
                       1600 байт на кадр  (без изменений)
        |
        v
BESM6_NITI_DECODE=proven: 6 байт на слово -> CalComp-байты
        |
        v
C ABI мост -> Plotter::calcomp_putch(char)
        |
        v
std::string calcomp  ->  Plotter::finish()
        |                       |
        |                       +-> calcomp.out   (сырой поток байтов)
        |                       +-> calcomp_convert_svg() -> calcomp.svg
        v
DUDKA: DUBNA-PLOT device=calcomp  (строка диагностики в логе)
```

Ожидаемый контракт C ABI моста (реализуется владельцем `dispak/`, здесь
только перечисляется): функции `calcomp_putch`, `tektronix_putch`,
`watanabe_putch`, `change_page`, `finish`. В этой проверке используется
только calcomp-ветка. Tektronix и Watanabe остаются дополнительными
выходами Дубны и в этом тесте не требуются.

Важное свойство: `plot.dat` остаётся единственным исходным артефактом
dispak и сохраняет прежний формат и прежние SHA. `calcomp.out` и
`calcomp.svg` это новые побочные файлы. Если мост меняет `plot.dat`,
тест считается проваленным, даже если SVG красивый.

## 2. Таблица analogue vs original

| Узел | Дубна (original, проверено по исходникам) | dispak (analogue) | Статус |
|---|---|---|---|
| Включение графики | карта `*call plotter:calcomp,direct`, `*call plotter:tektronix,direct`, `*call plotter:wx4675,direct` (`examples/grafor/README.md:6-12`, `calcomp.dub`) | дека запускается без карты `plotter`, графический контур вызывается через PERSO и ЭК 01210/01211 | аналог, разные точки входа |
| Вызов из программы | Grafor: `CALL PAGE`, `CALL LIMITS`, `CALL SYMBOL`, `CALL ENDPG` (`calcomp.dub`) | `CALL PAGE`, `CALL MOVE`, `CALL PLOT`, `CALL ENDPG` из PERSO 4.12 | аналог, разные программы и координаты |
| Выдача байта CalComp | ЭК `*57`, адрес 2: `machine.plotter.calcomp_putch(core.ACC)` (`e57.cpp:42-46`) | `BESM6_NITI_DECODE=proven` превращает 6 байт слова в CalComp-байты и вызывает тот же `calcomp_putch` | analogue: та же функция-приёмник, другой источник байтов |
| Векторный вывод | ЭК `*61 77777`: Watanabe при `ACC>>36 = 0`, Tektronix при `01400` (`extracode.cpp:678-703`) | не используется в этой проверке | original, в мосте не задействован |
| Смена страницы | ЭК `*50 066` вызывает `machine.plotter_change_page()` (`e50.cpp:431-436`) | `PAGE`/`ENDPG` формируют кадры `plot.dat`, мост завершает накопленный поток через `finish()` | аналог, не тождество |
| Кодирование команды | 01 = `-X`, 02 = `+X`, 04 = перо вверх, 010 = перо вниз, 020 = `+Y`, 040 = `-Y` (`plotter.cpp:398-418`) | те же биты, но полученные из 6-байтного представления слова `plot.dat` | переиспользование proven-кода |
| Рендер SVG | `Plotter::calcomp_parse()` и `calcomp_convert_svg()` (`plotter.cpp:318-391`) | тот же C++ код через C ABI | переиспользование без копирования алгоритма |
| Эталон | `tests/expect_calcomp_output.bin`, `tests/expect_calcomp.svg` | собственный SHA между двумя прогонами, а не сравнение с эталоном | эталон Дубны неприменим, см. раздел 5 |

## 3. Команды запуска

Базовый запуск из корня репозитория:

```
./verify/dubna-bridge/run.sh
```

С явными путями и сохранением временных файлов:

```
DISPAK_BIN=/home/azizz/Yandex.Disk/dispak/build/dispak/dispak \
NITI_2348=$HOME/.besm6/2348 \
KEEP_WORK=1 \
./verify/dubna-bridge/run.sh
```

Переменные:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `DISPAK_BIN` | путь к бинарнику dispak с подключённым мостом | `/home/azizz/Yandex.Disk/dispak/build/dispak/dispak` |
| `NITI_2348` | рабочий диск 2348 с библиотекой PERSO | `$HOME/.besm6/2348` |
| `TMPDIR` | основа для временного каталога | `/tmp/.private/azizz/opencode` |
| `KEEP_WORK` | если непусто, временный каталог не удаляется | unset |
| `REF2148` | системный диск 2148 | `/usr/local/share/besm6/2148` |
| `TIMEOUT` | таймаут одного прогона, секунды | `240` |
| `VERBOSE` | если непусто, печатать детали всех шагов | unset |

Раннер копирует диски 2048, 2053, 2099, 2148 и 2348 во временный каталог,
прогоняет деки `verify/C1-line.b6` и `verify/niti-lowlevel/t02-frame.b6`
дважды с `BESM6_NITI_DECODE=proven` и `BESM6_DUDKA_TEST=1`, затем сравнивает
SHA. `ctest` не запускается намеренно: это делает lead.

## 4. Критерии прохождения

Для каждой из двух дек в обоих прогонах:

1. В логе есть ожидаемая строка `NITI: summary ...` с прежними счётчиками
   кадров и слов.
2. SHA `plot.dat` совпадает с зафиксированным:
   C1 `7b362ec4efd7...` (3200 байт), t02 `27440f92e4c5039...` (1600 байт).
3. В логе есть строка `DUDKA: DUBNA-PLOT device=calcomp`.
4. Созданы непустые `calcomp.out` и `calcomp.svg`.
5. SHA `calcomp.out`, `calcomp.svg` и `plot.dat` одинаковы между прогоном 1
   и прогоном 2.

Итог раннера: `Summary: 2 PASS, 0 FAIL`. Любое несовпадение это FAIL с
указанием конкретной причины.

## 5. Честные оговорки

1. Схема БЕНСОН/НИТИ и CalComp эмулятора Дубны это разные устройства.
   У БЕНСОНа шесть линий `+X/-X/+Y/-Y/перо`, шаг 0.1 мм и команды NASA
   TM-76182 `6502/6514/6501/6504/6511/6512` для Электроники-1001
   (`docs/BENSON-PROTOCOL.md`). У CalComp Дубны байтовый поток с битами
   01/02/04/010/020/040. Совпадение битов `+X/-X/+Y/-Y` не делает протоколы
   одинаковыми: различаются носитель, адресация, смена страницы и единицы измерения.
2. Формат `plot.dat` это 64 слова по 8 шестибитных групп, а не байты
   CalComp. Режим `proven` это описание отображения «шесть байт слова в
   команды CalComp», а не доказанный исторический протокол БЭСМ-6. Слово
   «proven» относится к приёмнику (`plotter.cpp`, проверенный эталонами),
   а не к происхождению формата НИТИ.
3. Протокол выдачи БЕНСОНа для НИТИ в доступных исходниках не найден.
   Гипотеза 13+2+1 в `dispak/extra.c` и NASA-аналог остаются гипотезами.
4. Нельзя требовать совпадения `calcomp.out` с
   `tests/expect_calcomp_output.bin`: там рисует другая программа
   (`examples/grafor/calcomp.dub`, строка `Calcomp`) с другими координатами.
   Аналогично `docs/NITI-CALL-DETAILED.md:582` объясняет разницу между
   нативным портом и тестом C1 разными программами, а не несовместимостью.
5. На момент подготовки бэкенд не собран. Раннер проверяет маркеры в
   бинарнике и печатает FAIL, если мост отсутствует. Заполнять ожидаемые
   SHA `calcomp.out`/`calcomp.svg` до реального прогона запрещено.
6. В таблице выше и в тексте встречаются латинские имена файлов и кода,
   это идентификаторы, а не переводы.
