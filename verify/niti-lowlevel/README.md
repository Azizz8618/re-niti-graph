# Низкоуровневые тесты экстракодов НИТИ (B2)

Набор проверяет «функциональный слой» НИТИ в эмуляторе **dispak** напрямую,
без Fortran/PERSO: МАДЛЕН-деки вызывают экстракоды ЭК 50 через `*assem`.

Дополняет высокоуровневые тесты `verify/C1-line.b6` … `C5-counters.b6`
(тесты FOREX 4.12), которые уже все PASS.

Обработчики (`dispak/dispak/extra.c`):

| ЭК | Действие |
|----|----------|
| 01210 / 01216 / 01217 | `niti_select(reg[016])` → `NITI: scheme NNNN selected`, `niti_active=1` |
| 01211 | `niti_frame()` → 64 слова в `plot.dat`, если `reg[3]==071717` **или** `niti_active` |

В конце работы через `atexit` печатается
`NITI: summary schemes=N frames=N words=N active=N scheme=N`.

## Состав

| Файл | Что делает |
|------|------------|
| `t01-select-1210.b6` | Только `*50,1210`, кадра нет. Ожидается `scheme 1210`, summary `schemes=1 frames=0 words=0`, `plot.dat` отсутствует |
| `t02-frame.b6` | `*50,1210` + один `*50,1211`. summary `1/1/64`, один кадр |
| `t03-two-frames.b6` | `*50,1210` + два `*50,1211`. summary `1/2/128`, два кадра в одном файле |
| `t04-scheme-1216.b6` | `*50,1216` + кадр → в summary `scheme=1216` |
| `t05-scheme-1217.b6` | `*50,1217` + кадр → в summary `scheme=1217` |
| `t06-legacy-71717.b6` | Без выбора схемы, но `3,VTM,71717B` перед `*50,1211`. Старый путь: summary `schemes=0 … active=0`, строки `NITI: scheme …` нет |
| `run.sh` | Раннер: копирует диски во временный каталог, прогоняет все 6 дек, сверяет лог и `plot.dat`, печатает таблицу PASS/FAIL |

`.localdocs/niti-b2/niti-1210.b6`. Каждая декой завершается `*62,0B` и `,END,`.

## Что проверяется

Для каждой деки:

* строка `NITI: scheme NNNN selected` (для t06 — её **отсутствие**);
* точная строка `NITI: summary …` с ожидаемыми `schemes/frames/words/active/scheme`;
* `plot.dat`: количество строк, размер в байтах, SHA256 и структура строк
  (ровно 8 двухзначных восьмеричных чисел в каждой строке);
* для t01 — `plot.dat` **не должен** существовать (кадр не писался);
* `КОНЕЦ ЗАДАЧИ` в логе и отсутствие `ОШ / ОШИБКА / ОТСУТСТВУЕТ / ERR n`
  (включая латинскую транслитерацию сообщений монитора).

## Формат plot.dat

Каждая строка — одно 48-битное слово кадра, разбитое на 8 групп по 6 бит.
Формат вывода в `extra.c`: восемь полей `%02o ` и перевод строки:

```
00 00 00 00 00 00 00 00 \n
```

Одно поле занимает 3 байта (две восьмеричные цифры + пробел), строка —
**25 байт** (8 × 3 + `\n`). Поэтому:

* 64 слова = 64 строки = **1600 байт**;
* 128 слов = 128 строк = **3200 байт**.

В формулировке задачи было указано 1536 / 3072 байт (25 байт на строку
не учитывался, 24 × 64 и 24 × 128). Фактическая реализация пишет перевод
строки (`fputc('\n')`) после каждого слова, поэтому раннер проверяет
реально получаемые 1600 / 3200 байт, а не 1536 / 3072. Это расхождение
в ожидании, а не дефект теста: это в точности соответствует `extra.c:100-106`.
