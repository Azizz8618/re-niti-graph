# Ожидаемое содержимое plot.dat (этап C)

## Формат файла

`plot.dat` открывается один раз за прогон (`dispak/extra.c`, `/01211`) и
дополняется кадрами. Один кадр = 64 слова БЭСМ-6; каждое слово печатается
отдельной строкой как 8 восьмеричных 6-битных групп:

```
00 074 0000 00 000 000 ...   (8 групп на строку)
...                          (всего 64 строки на кадр)
```

Поэтому «1 кадр» в таблице ниже = 64 строки, а не одна строка файла.
Допустимые символы: цифры `0..7`, пробелы, перевод строки. Всё остальное
(служебный текст, кадр целиком из нулей, обрыв строки) — мусор.

Точное соответствие между внутренними координатами порта и 6-битными
группами зависит от реализации прослойки B2, поэтому ниже описаны
инварианты (число кадров, монотонность, различие координат), а не
конкретные восьмеричные числа. Как только эталон с original GRAFOR будет
получен, конкретные значения нужно зафиксировать здесь же.

## Инварианты для всех тестов

- файл существует, непуст, число строк кратно 64;
- нет кадров, состоящих только из `00`;
- кадры для разных точек не совпадают побайтово;
- в логе: баннер `4.12`, `КОНЕЦ ЗАДАЧИ`, нет `ОШ` / `OTCYTCTBYET`;
- если B2 пишет трассировку, в логе есть строки `NITI:`.

| Тест | Вызовы в деке | Ожидаемые кадры (строки) | Что проверить в координатах |
|---|---|---|---|
| C1-line | PAGE, MOVE(10,10), PLOT, MOVE(110,110), PLOT, ENDPG | 2 кадра от PLOT (128 строк), плюс до 2 кадров обрамления PAGE/ENDPG | две разные точки, рост первой координаты от ~10 к ~110; обе точки ненулевые; прямая без промежуточных разрывов |
| C2-circle | ARCIA(...,12 шагов по 0.5236 рад) + CIRCLE(...,12) | не менее 12 кадров от ARCIA (768 строк); CIRCLE добавляет кадры только если MOVE эмитирует в B2 | угол монотонно растёт шагом 30 градусов, радиус около 50, центр около (100,100); соседние кадры различимы |
| C3-text | 2 × SYMBOL + NUMBER(...,123) | не менее 6 кадров глифов (384 строки; NUMBER рисует 6 цифр) | повторяющиеся разреженные битовые узоры глифов, а не сплошные нули; между кадрами есть сдвиг по X |
| C4-page | две пары PAGE/ENDPG, по одному PLOT на страницу | не менее 2 кадров точек + 2 завершающих кадра страницы (минимум 128, типично 256 строк) | кадры второй страницы отличаются от первой (MOVE в (50,50) против (10,10)); в логе обязателен `КОНЕЦ ЗАДАЧИ` |
| C5-counters | 3 × PLOT, печать /TRACE/ | 3 кадра от PLOT (192 строки) | в логе строка `NITI-C5 NEXC50-74 NPLOT` с `NPLOT >= 3`; NEXC50/NEXC70 должны быть неотрицательными и расти вместе с вызовами |

## Как отличить корректный вывод от мусора

1. Кратное 64 число строк и стабильный SHA256 между повторными прогонами
   одной и той же деки на одной и той же сборке.
2. Разные деки дают разные `plot.dat` (C1 не равен C2 и т.д.).
3. В C2 угловой порядок не «прыгает»: соседние кадры отличаются
   небольшим приращением, а не случайной перестановкой групп.
4. В C3 глифы имеют повторяющуюся структуру (одинаковая цифра даёт
   одинаковый узор), а не случайный шум.
5. Если все кадры нулевые или файл содержит только один кадр при любом
   числе PLOT — прослойка B2 не получает координаты, даже если пишет
   `NITI:`-строки; это не считается прохождением теста.
