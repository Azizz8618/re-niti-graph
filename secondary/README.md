# Вторичный каталог библиотеки 22 (зона `0o1163` тома 2048): дизассемблирование тел точек входа

После расшифровки пар «имя / дескриптор» в зоне `0o1163` (90 ненулевых слов, 36 имён)
были вырезаны тела по 15 записям с ненулевым дескриптором и дизассемблированы.
Остальные 21 запись имеют малое значение (1..134) и не содержат адреса тела.

## Метод и формула

Формула из `extract/decode_catalog.py` (проверена на 238 модулях основного каталога):

```
relzone = (B - 0o40) & 0o77      carry = 1 если relzone >= 0o40, иначе 0
word    = A - 0o2000 - carry - 8
body_zone = 0o1100 + relzone     load = C / 8
```

Исходные слова: `/tmp/.private/azizz/opencode/grafor22/zone_11xx.bin`
(1024 слова × 6 байт big-endian; совпадают с `extract/bin/zone_581.bin` для `0o1105`).
Срезы сохранены в `bin/<NAME>.bin`, полный лог попыток — `explore_targets.log`,
дешифровка каталога — `catalog_decode.txt` и `decode.json`, карта ненулевых
областей зон — `region_map.txt`.

Важно: в задании предлагалось `word≈0o1077` для `PLOT`; по проверенной формуле
получается `0o1100` (576), разница в 1 слово. Проверены оба адреса: оба попадают
в одну и ту же область кода, вердикт от этого не меняется.

### Почему `dtran -F dms` не работает напрямую

Тела вторичного каталога — **не DMS-модули**: у них нет заголовка `head=1`.
Поэтому прямой `dtran -F dms`:

- `PLOT`, `LPL`, `ARC`, `XYSORT` — падает с `rc=-11` (signal 11): первые три слова
  дескриптор читает как `head/sym/debug/cmd/const` и уходит в несуществующее смещение;
- `GROPEN`, `WRITC`, `MDBUFF`, `ENDPG` — компилируется, но пишет
  `File was too short: N, expected <огромное число>`;
- `.bin` с нулями (`MOVE`, `PAGE`, `SET`, `BRLINE`, `FULL`, `BROKEN`) dtran
  принимает за пустой DMS-модуль: `C Commands: 0 ... ,END,` — это честный
  результат, а не ошибка инструмента;
- `ARC` без `-F` автоопределился как Pascal-A (`Format: Pascal-A`), что тоже
  ошибка: это другой формат.

Обход: к срезу дописывается **синтетический DMS-заголовок** из трёх слов
(`head=0, sym=0, debug=0`, `set=data=long=0`, `cmd = число слов фрагмента`),
после чего `dtran -F dms` выдаёт осмысленные мнемоники МАДЛЕН. Такие входные
файлы лежат в `bin/<NAME>_synth.bin`; результат — в `madlen/<NAME>.mad`.
Для полностью нулевых тел `.mad` содержит только `,END,` — это отражено в таблице.

Параллельно все срезы прогнаны через `disbesm6 -a0 -e0`; сырые листинги —
`<NAME>.rawdis.txt`. Именно они показывают, что в `*50`-подобных словах лежит
настоящий код, даже когда dtran отказывается работать.

## Главный вопрос: затёртые программы или специальные заглушки?

**Это программы, которые были затёрты/перезаписаны, а не специально поставленные заглушки.**

Основание: по адресам из вторичного каталога для семи записей лежат осмысленные
команды МАДЛЕН с экстракодами Э50/Э60/Э63/Э70 (`PLOT`, `GROPEN`, `WRITC`,
`MDBUFF`, `LPL`, `ARC`, `XYSORT`). Заглушка, поставленная намеренно, выглядела бы
как короткий `13,UJ,` (ровно так сделана написанная командой прослойка
`verify/native/SHIM.mad`) или как пара «возврат/нули»; здесь же видны рабочие
последовательности из десятков инструкций с манипуляциями регистрами и вызовами
экстракодов.

Для восьми записей (`MOVE`, `PAGE`, `ENDPG`, `SET`, `SYMBOL`, `BRLINE`, `FULL`,
`BROKEN`) тела действительно утрачены: каталог продолжает сообщать ненулевую
длину (12..259 слов), но по указанным адресам стоят нули либо чужой DMS-модуль
(`ENDPG` → SYMTAB). Столь длинный нулевой участок не похож на намеренную
заглушку: настоящая заглушка занимала бы 1-2 слова, а не 116/233/259.
Наиболее правдоподобная причина — вторичный каталог застарел: его тела находились
в зонах 0o1102..0o1105, которые позже частично перезаписали модули основного
каталога (BCD, SYMTAB, NUMBER, LIMITS, REGION в зоне 0o1105).

Единственный случай «заглушечного» характера — 21 запись с малым дескриптором
(`RDB`, `IRDB`, `PEN`, `FRAME`, ...): это ссылки на точки входа драйвера без тела
в этой библиотеке. Но и они не «программы-заглушки», а каталожные ссылки.
Поэтому ответ пользователю: **вторичный каталог описывает реальные низкоуровневые
программы ГРАФОР-СУД; часть из них сохранилась, часть стёрта, и только малые
записи не имеют тела изначально.**

## Ограничения

- Синтетический DMS-заголовок даёт мнемоники, но не восстанавливает метки и
  символическую таблицу исходного модуля: у фрагментов их никогда не было.
- `nonzero` считается по объявленному `load`, который для `LPL` (2094) и `PAGE`
  (180) заведомо завышен/переходит границу зоны; в таблице это помечено звёздочкой.
- Проверка по образу диска (`/usr/local/share/besm6/2048`) не производилась:
  использовались готовые дампы зон из `/tmp/.private/azizz/opencode/grafor22/`.
- Каталог `0o1163` содержит NAME-пары только до слова 73; слова 75..91 —
  служебные/текстовые (`catalog_tail.txt`), к телам отношения не имеют.
