# Набор тестовых рисунков графопостроителя

Каталог `verify/drawings/` содержит 8 дек, которые рисуют разные геометрические
фигуры через тот же тракт, что и базовая дека `verify/C1-line.b6`:

```
FOREX MOVE -> /GFAFTR/ -> PLOT -> /PDEVXY/ -> PDEV -> ЭК 1210/1211
          -> plot.dat -> coords-декодер -> benson.out -> plotter.cpp -> benson.svg
```

Цель набора: подтвердить, что изменение только координат не ломает
графопостроителя и что вывод детерминирован.

## Критическое ограничение: адрес `/PDEVXY/`

В `fortran/verify/PDEV.mad:19,21` адрес COMMON `/PDEVXY/` захардкожен как
`0o3147`. Это адрес из кросс-ссылок базовой деки (`*PDEVXY* C 03147`). Если
скомпилированная программа станет длиннее, COMMON переедет, `PDEV` будет
читать не те слова, и кадр декодируется в `(0,0)` вместо координат. Внешне
это выглядит как валидный, но пустой `benson.svg`.

FOREX 4.12 дедуплицирует константы, и размер пула равен `4 + 2*N` восьмеричных
слов, где `N` число различных значений среди четырёх координат:

| N | `KOHCTAHT` | `*PDEVXY*` | Рисунок |
|---:|---|---|---|
| 1 | `00006` | `0o3145` | пустой |
| 2 | `00010` | `0o3147` | работает |
| 3 | `00012` | `0o3151` | пустой |
| 4 | `00014` | `0o3153` | пустой |

Поэтому каждая дека:

- побайтно повторяет `verify/C1-line.b6` за исключением строк 34 и 36
  (две строки `CALL MOVE`);
- сохраняет 45 строк, Names `C1LINE`, `*name C1LINE`, 2 пары `MOVE`/`PLOT`,
  `PAGE`/`ENDPG` и `PRINT 900, NPLOT`;
- использует ровно два различных числовых значения координат.

Пробная дека с четырьмя парами `MOVE`/`PLOT` для замкнутого прямоугольника
дала `KOMAHД 00033`, `*PDEVXY* C 03155`, `NPLOT=4`, `frames=4`, но `benson.svg`
с 0 элементами `<path>`. Замкнутый контур при сохранении адреса невозможен,
поэтому `d04` это две стороны (низ плюс правая) с разомкнутым контуром.

Следствие ещё жёстче: с двумя значениями `A`, `B` приращения равны `0`, `+d`
или `-d`, поэтому у основного штриха доступны только наклоны `0`, `∞`, `+1`, `-1`.
`d06` и `d07` это предельные варианты (вертикаль и горизонталь), а не
промежуточные наклоны.


## Проверки

На каждой деку делается два прогона (r1 и r2). Дека считается PASS, если в
обоих прогонках:

- есть `NITI: summary` и `КОНЕЦ ЗАДАЧИ`, нет `ОШ`, `ОШИБКА`, `ERR N`,
  `ОТСУТСТВУЕТ`, `OWIBKA`, `OTCYTCTBYET`;
- кросс-ссылка `*PDEVXY* C 03147` (адрес не уехал);
- `benson.out` непуст;
- `benson.svg` непуст, первая строка начинается с `<?xml`, есть `<path`;
- SHA256 `benson.out` и `benson.svg` одинаковы между r1 и r2.

Дополнительно в таблицу выводятся размер SVG (`width` x `height`), число
`<path>`, NPLOT и 12-символьные префиксы хэшей. Итоговая строка требует
минимум 6 PASS и отсутствия FAIL.

## Честные оговорки

- `benson.out` и `benson.svg` помечены `[аналог NASA, БЕНСОН-501]`. Это не
  реальный протокол НИТИ/БЭСМ-6, а проверенный бэкенд рендеринга.
- SVG не повторяет «идеальную» геометрию: перемещение идёт сначала по X,
  затем по Y; ось Y в SVG перевёрнута (`y = maxy - ben.y`); первый `<path>`
  это соединитель от `(0,0)` к первой точке `MOVE`; совпадающие по направлению
  точки схлопываются. Диагональ поэтому выглядит как L-образная ломаная.
- Хэши зависят от конкретной сборки dispak, образа диска и побайтного
  содержимого дек. Сравнивать хэши имеет смысл только на одной и той же
  конфигурации.
- Все координаты лежат внутри 0..200 шагов (0..20 мм) и не приближаются к
  лимиту `ben.limit 5000x7500`, поэтому ошибок `LIMIT X`/`LIMIT Y` нет.
- Временные файлы создаются только в `TMPDIR`; при `KEEP_WORK` не заданном
  рабочий каталог удаляется.Git commit и push не выполнялись.
