# Набор тестовых рисунков графопостроителя

Каталог `verify/drawings/` содержит 10 дек, которые рисуют разные геометрические
фигуры через тот же тракт, что и базовая дека `verify/C1-line.b6`:

```
FOREX MOVE -> /GFAFTR/ -> PLOT -> /PDEVXY/ (адрес аргументом) -> PDEV
          -> ЭК 1210/1211 -> plot.dat -> coords-декодер
          -> benson.out -> plotter.cpp -> benson.svg
```

Цель набора: подтвердить, что изменение координат и числа точек не ломает
графопостроителя и что вывод детерминирован.

## Адрес кадра больше не ограничен

Раньше `fortran/verify/PDEV.mad` захардкожил адрес COMMON `/PDEVXY/` =
`0o3147`, из-за чего любые три-четыре различных значения координат или
дополнительная пара `MOVE`/`PLOT` сдвигали COMMON и давали пустой SVG.

Теперь `PLOTSTUB` вызывает `CALL PDEV(FRAME(1))`. Адрес единственного
аргумента приходит в сумматоре; `PDEV.mad` сохраняет его в R11 (`ATI`),
выталкивает сохранённый сумматор из магазина (`STX`) и загружает адрес
обратно перед каждым ЭК (`ITA`). Поэтому длина дека и размер пула
констант больше не важны.

Наблюдённые адреса (только для справки, не критерий):

| Деки | `*PDEVXY*` | Кадров | `<path>` |
|---|---|---:|---:|
| d01..d08 | `0o3150` | 2 | 2 |
| d09-triangle | `0o3155` | 3 | 3 |
| d10-quad | `0o3160` | 4 | 4 |

Старое значение `0o3147` относилось к деке без аргумента у PDEV; после
добавления `FRAME(1)` базовая дека даёт `0o3150`. Контрольные хэши
`verify/C1-line.b6` при этом не изменились.

Оговорка: MADLEN не умеет разрешать внешние символы FOREX по имени, а FOREX
не поддерживает ассемблерные вставки внутри FORTRAN-исходника. PDEV поэтому
остаётся отдельным МАДЛЕН-модулем, собираемым в PERSO-зоны `0o2750` и
`0o2760` (`fortran/verify/build-niti-disk.sh`); связь с FORTRAN идёт через
соглашение вызова, а не через имя COMMON.

## Запуск

```
cd /home/azizz/Yandex.Disk/re-niti-graph
DISPAK_BIN=/home/azizz/Yandex.Disk/dispak/build/dispak/dispak \
TMPDIR=/var/tmp ./verify/drawings/run.sh
```

Переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DISPAK_BIN` | `/home/azizz/Yandex.Disk/dispak/build/dispak/dispak` | бинарник dispak с бэкендом БЕНСОНА |
| `NITI_2348` | `~/.besm6/2348` | рабочая копия диска с портом в свободных зонах от `0o2410` (системные зоны и Глиссада-6 восстановлены) |
| `TMPDIR` | `/var/tmp` | каталог для временных файлов |
| `KEEP_WORK` | не задан | сохранить рабочий каталог для разбора |
| `REF2148`, `TIMEOUT`, `VERBOSE` | системные / 240 / пусто | доп. настройки |

Раннер сам выставляет `BESM6_DUDKA_PLOT=benson`, `BESM6_DUDKA_TEST=1` и
`BESM6_DUBNA_PLOT_KEEP=1`. ctest не вызывается. Если в бинарнике нет маркера
`BESM6_DUDKA_PLOT`, раннер сразу печатает FAIL и не выдумывает артефакты.

Пример с сохранением логов:

```
TMPDIR=/var/tmp KEEP_WORK=1 ./verify/drawings/run.sh | tee /var/tmp/drawings.log
```

## Проверки

На каждой деку делается два прогона (r1 и r2). Дека считается PASS, если в
обоих прогонках:

- есть `NITI: summary` и `КОНЕЦ ЗАДАЧИ`, нет `ОШ`, `ОШИБКА`, `ERR N`,
  `ОТСУТСТВУЕТ`, `OWIBKA`, `OTCYTCTBYET`;
- `benson.out` непуст;
- `benson.svg` непуст, первая строка начинается с `<?xml`, есть хотя бы один
  `<path>`, размеры `width >= 2` и `height >= 1`;
- SHA256 `benson.out` и `benson.svg` одинаковы между r1 и r2.

Адрес `/PDEVXY/` из кросс-ссылки выводится в таблицу для справки и больше
не проверяется. Итоговая строка требует, чтобы прошли все 10 дек.

## Честные оговорки

- `benson.out` и `benson.svg` помечены `[аналог NASA, БЕНСОН-501]`. Это не
  реальный протокол НИТИ/БЭСМ-6, а проверенный бэкенд рендеринга.
- SVG не повторяет «идеальную» геометрию: перемещение идёт сначала по X,
  затем по Y; ось Y в SVG перевёрнута (`y = maxy - ben.y`); первый `<path>`
  это соединитель от `(0,0)` к первой точке `MOVE`; совпадающие по направлению
  точки схлопываются. Диагональ поэтому выглядит как L-образная ломаная.
- Хэши зависят от конкретной сборки dispak, образа диска и побайтного
  содержимого дек. Сравнивать хэши имеет смысл только на одной и той же
  конфигурации.
- Все координаты лежат внутри 0..200 шагов (0..20 мм) и не приближаются к
  лимиту `ben.limit 5000x7500`, поэтому ошибок `LIMIT X`/`LIMIT Y` нет.
- Временные файлы создаются только в `TMPDIR`; при `KEEP_WORK` не заданном
  рабочий каталог удаляется через `trap`. Git commit и push не выполнялись.
