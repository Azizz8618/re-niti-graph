# Физический уровень графопостроителя: Э50/ТРУБКА/ДУДКА и КАДОПАМ-ДКС

Назначение документа — объяснить, как результаты вычислений библиотеки 22 (ГРАФОР-СУД)
доходил до «железа» графопостроителя, и почему в современных исходниках
почти нет прямых вызовов.device-кодов из Фортрана.

Все утверждения ниже снабжены путями к исходникам. Неподтверждённое
помечено как `[I]` или « расхождение источников ».

---

## 1. Два разных физических канала (главное различие)

В среде БЭСМ-6/Диспак сосуществуют **два независимых канала**, которые
часто путают:

| Канал | Команды/вызовы | Что обслуживал | Где описан |
|---|---|---|---|
| **Графопостроитель (ГП)** | Экстракоды **Э50 1200…1207**, Э52 12xx, Э50 7600 | БЕНСОН, ГРАФИК, табло, ГП по схеме НИТИ | `re-dispak/rukava.be:3028-3039`; `re-dispak/ai/справочник_ТРУБКА_ДУДКА.md` |
| **КАДОПАМ / ДКС** | Машинные команды **032** (чтение) и **0132** (запись), 4 канала × 32768 16-битных слов | Терминалы Э-60/МИДИКОН, М-7000, связь с удалённой машиной | `re-dispak/AGENTS.md:1050-1090`; `re-glissade/docs/analysis/dks-bridge-runbook.md` |

Прямой цитатой это зафиксировано в `re-glissade/docs/PLAN-DIALOG.md:53-56`:
«графика БЭСМ-6 — это Э50 1200…1207 (ГРАФИК/БЕНСОН), другое устройство»;
КАДОПАМ — это «команды 032 (чтение слова Э-60) и 0132 (запись, 077777 =
«звонок»)».

**Вывод:** сам графопостроитель не «висел» на КАДОПАМе. КАДОПАМ-ДКС
обеспечивал связь с удалённой машиной (Э-60), к которой мог быть подключён
графопостроитель или через которую маршрутизировался вывод.

## 2. Локальный путь: библиотека 22 -> Э50 -> ТРУБКА -> ДУДКА -> БЕНСОН

### 2.1 Что делает библиотека 22

В самой библиотеке 22 **нет кода привода пера**. Есть только:
- вычисление координат в общих блоках (`*GFBFTR*`, `*GFATRN*`, `*GFBLAN*`,
  `*GFNTCH*`, `*GFGOBS*`);
- передача управления внешним точкам входа из вторичного каталога зоны
  `0o1163`: `PLOT`, `PEN`, `ONOFF`, `FRAME`, `FRAGM`, `EFRAGM`, `GROPEN`,
  `GRWRIT`, `GRCLOS`, `GRNOTZ`, `GRNAME`, `WRITC`, `ENDPG`, `PAGE`, `SET`,
  `IDENT`, `ITALIC`.

Примеры: `MOVE1.mad:37` — `PLOT :,SUBP,` (объявление внешней точки),
`MOVE1.mad:206` — `13,VJM,PLOT`. То есть `PLOT` — не тело в библиотеке,
а **контракт** с системным драйвером.

### 2.2 Точка Э50 внутри библиотеки 22

Модуль `*70` (`madlen/_s70.mad`) — единственный в библиотеке, кто прямо
вызывает Э50 с «графическим» кодом:

```
_s70.mad:68   ,*50,1206B      ! Э50 1206
_s70.mad:82   ,*50,115B       ! Э50 115 (обмен с external memory)
_s70.mad:83   9,*72,
_s70.mad:85   ,*50,116B
```

`E70.mad:23` (`13,VJM,*70`) — тонкая обёртка; `RZON.mad:32-33` передаёт
управление либо в `E70`, либо прямо в `*70`. Это и есть нижняя граница
библиотеки: выше — координаты, ниже — системный вызов Э50.

### 2.3 Системный обработчик ТРУБКА

`re-dispak/trubka.be`, загрузка по `10000₈`, 1 лист; системный модуль
управления ГП. Принимает экстракоды Э52 с кодами `1200-1217` и `1240`
(`ai/справочник_ТРУБКА_ДУДКА.md`, ч.1-2). Ключевые шаги:

1. `trubka.be:35-70` — вход: анализ служебного вызова, выделение номера
   задачи (П77), адрес ИПЗ, номер физического канала/листа в М3.
2. `trubka.be:479` (`ЛИСТЧ`) — формирование КУС ГП; код 1200 превращается
   в Э5200.
3. `trubka.be:283` (`Э5200`) — разбор подфункции; `gпнити` (`:679`) для
   кодов `1210-1217` (схема НИТИ).
4. `trubka.be:132` (`ОБМЕН`) и `:716` (`нафиз`) — формирование КУС и вызов
   `ФИЗОБМ` (физический обмен).

### 2.4 Драйвер БЕНСОНА ДУДКА (схема НИТИ им. Александрова)

`re-dispak/dudka.be` — драйвер ГП «БЕНСОН» для конфигурации НИТИ.
Алгоритм из шапки (`dudka.be:1-42`):

1. Загружается **из ТРУБКИ** по Э52 `1210` (или `1216/1217`) через
   `gпнити`. Выделяются **два буферных листа ОЗУ** через `ТБУФ`.
2. Формируются два КУС: `D10164` (чтение данных из внешней памяти в
   буфер) и `D10163` (запись кадра в БЕНСОН). Оба содержат **бит 27**
   (`е27гп`, признак ГП) и номер устройства/направления (маска `D10120`
   = `0070000000001600`).
3. Инициализация БЕНСОНА: в спец. регистр `РЕГ '34'` последовательно
   пишутся 9 управляющих слов (маски `Е28`, `Е28Е25`, `Е28Е21`, `D10171`).
4. Подменяется вектор прерывания `обвнп1+30` (18-й разряд ГРП); новый
   обработчик — `ВХОД`.
5. Основной цикл: `вдудку` формирует кадр; `ФИЗОБМ` передаёт его в
   БЕНСОН; по прерыванию из `РЕГ '240'` читается слово данных; после
   заполнения буфера — переключение буферов и пробуждение задачи.
6. По завершении (бит 48 во 2-м слове ИПЗ) БЕНСОН сбрасывается, вектор
   восстанавливается, буферы возвращаются через `ТБУФ`.

Регистры: `РЕГ '34'` — запись команды управления, `РЕГ '240'` — чтение
слова данных, `УВВ '4023'` — опрос состояния, `УВВ 7` — команда
физического обмена, `ТВ67/ТВ67А` — установка/гашение масок ГРП.

Это и есть **физический уровень в буквальном смысле**: не «печать в файл»,
а прямое управление регистрами устройства и прерываниями.

Именно поэтому название проекта `re-niti-graph` («НИТИ») не случайно:
схема подключения ГП «НИТИ им. Александрова» — тот самый вариант, для
которого написан ДУДКА (`dudka.be:2-3`).

## 3. Удалённая машина и КАДОПАМ-ДКС

### 3.1 Историческая маршрутизация вывода на ГП

Инструкция `besm6-new/besm6-legacy/krab/doc/sграф` («ИНСТРУКЦИЯ ДЛЯ ВЫВОДА
НА ГРАФОПОСТРОИТЕЛЬ») задаёт пакет:

```
шифр ХХХХХХ ЗСМ^
ВЫВ ГП 36^
...
ЕЕВ1А3
*NАМЕ ГРАФОР
*LIВRА:17
   ТЕКСТ ПРОГРАММЫ
*ЕХЕСUТЕ
*ЕND FILЕ
```

Комментарий в документе прямо указывает: «36 — номер абонента сети,
обслуживающего графопостроитель». То есть **задача не знает, где стоит
ГП**: она отправляет вывод сетевому абоненту 36, а тот уже управляет
устройством. Это и есть удалённая машина (remote plot server).

Там же: «изменён номер библиотеки ГРАФОРА — раньше `*LIВRА:24`, теперь
`*LIВRА:17`», и пример вызова `CALL РАGЕ(ХL,УL,НАМЕ,N,J)` с `J=1`, чтобы
шифр задачи печатался на бумаге при разрисовке. То есть Fortran/Pascal-
программа работает с GRAFOR как с обычной библиотекой, а маршрутизация
вывода — отдельный уровень пакета.

### 3.2 Как КАДОПАМ-ДКС технически связывает машины

`re-dispak/AGENTS.md:1070-1090`:
- память КАДОПАМ: **4 канала × 32768 16-битных слов**
  (`uint16_t e60_mem[4][32768]`);
- доступ командами `032`/`132` в формате `кк 26,'NNN'(Мx)`, где `NNN` —
  15-битный адрес внутри канала, `Мx` — смещение; старшие биты кодируют
  операцию (`0xx` — чтение, `70xx` — запись);
- ячейка 0 канала 0 при `032`-чтении возвращает
  `DKS_STATUS | слркс0 | счётчик`, где `DKS_STATUS = 02000` (бит 11 —
  «канал 0 готов»).

`re-glissade/docs/analysis/dks-bridge-runbook.md:190-220` показывает
реальный мост в SIMH: `SET DKS REMOTE=localhost:4140` на БЭСМ-6 и
`SET DKS BRIDGE=4140` на Э-60. В трассе:

```
032: [2]00000 -> 002000        ; чтение ячейки 0 через КАДОПАМ
0132: [2]77777 <- 000400       ; «звонок» БЭСМ-6
bridge: <- ATTN (ПРП 6) + ПРП12 ; системный запрос от Э-60
```

Модуль `СВЯЗЬ7` (`re-dispak/AGENTS.md:1050-1068`, зона `0677`) обрабатывает
ПРП5-8,12:соответствие ПРП = 8 − код канала (ПРП8 → канал 0, ведущая Э-60;
ПРП5 → канал 3, М-7000). При конфигурации `∧К71 = 1` загружается СВЯЗЬ7,
а **графопостроитель заглушается** (`загл7а`, `загл7б`) —
`re-dispak/AGENTS.md:981`.

### 3.3 Вариант К-71 / НИТИ

`rukava.be:3038-3039`: Э50 `1216`/`1217` = «ГП НИТИ (ДОП.
ОБОРУДОВАНИЕ, ВАРИАНТ К-71)». `trubka.be:673` (`gпнити`) по коду
подфункции `1210-1217` (`слиа -8(М3)`) загружает нерезидентный драйвер
ГП (ДУДКА) с МЛ/МБ. В ТРУБКЕ для К-71 есть входы `вхгп2а..вхгп2е`,
взаимодействующие с ДКС (`ai/справочник_ТРУБКА_ДУДКА.md`, ч.4).

**Итог по удалённому подключению:** графопостроитель мог стоять как на
локальной машине (Э50 → ТРУБКА → ДУДКА → БЕНСОН), так и за удалённым
сетевым абонентом/Э-60; во втором случае данные и прерывания шли через
КАДОПАМ (032/132) и `СВЯЗЬ7`, а сам драйвер и буферы могли находиться
на другой машине. Один и тот же вызов `PLOT`/`PAGE` в прикладной программе
при этом не менялся — менялась только маршрутизация на уровне пакета/ОС.

## 4. Код 1206 трассирован: это терминал, не графопостроитель

Расхождение источников разрешено по коду `ТРУБКИ`, а не по таблицам:

- `re-dispak/rukava.be:3034` относит Э50 `1206` к «ГРАФОПОСТРОИТЕЛЬ:
  БЕНСОН», но в графе «источник» стоит `?`.
- `re-dispak/docs/Dispak-sysprog-guide.md:3287-3295` и
  `re-dispak/zhurnal.be:937,1099` описывают Э50 `1206` как выдачу на
  **операторский терминал** сообщения «УСТ.СР.К…» / «УСТАНОВИ СРОЧНО…».

Полный путь по коду (`trubka.be`):

```
_s70.mad:67  3,VTM,71717B      ключ в М3
_s70.mad:68  *50,1206B         вызов Э50
trubka.be:47-55  вход, М3 := код подфункции из 8(М2)
trubka.be:283-295  Э5200: проверка диапазона и ключа 71717, табличный переход
trubka.be:316-317  ЭК1206: СЧ (М2); ПБ БОБН
trubka.be:550-580  БОБН: поиск бобины в ТЗНМЛ, сборка текста СРМГ
trubka.be:586-587  ВЫДТ1: СЧ E23; ПБ ТВ40  (печать на терминал)
```

Ни в одной строке ветки 1206 нет `ФИЗОБМ`, `ОБМЕН`, `ИДК`, `УВВ 7`,
`РЕГ '34'`, `РЕГ '240'`, `ТБУФ` или `гпнити`. Тексты сообщений:
`trubka.be:748-756` (`П'5УСТ С'`, `П'РОЧНО '`, `КИН = П'РЧ.К00'`).
Что `ТВ40` означает печать на терминал, доказано в `nombob.be:301-303`
(«Е23 – выдача на терминал», «ПБ ТВ40, вызов ТВ40 (печать на ТТ)»).

Источник: архивный вызов `archive/malichev_2048.md:3266` —
`,FUN,1206В.УСТ. СРОЧНО...`. В `dispak/extra.c:1788` ЭК 1206 тоже
обрабатывается как проверка наличия диска, а не как вывод графики.

**Текст сообщения.** По `docs/Dispak-sysprog-guide.md:3287-3304`, экстракод
выдаёт на операторский терминал строку:

```
УСТ.СР.К.N БХХХХ
```

где `ХХХХ` — номер тома МЛ/МД, который нужно установить, а `N` — номер
программного канала задачи. Перед вызовом на СМ (разряды 1-16) кладётся
номер тома в двоично-десятичном виде, в М3 — ключ `71717`. Если том уже
установлен, выдачи нет, а на СМ возвращается его номер в восьмеричном
виде. Вариант для области АРФА (`zhurnal.be:1099-1105`):
`УСТ.СРОЧНО ТОМ NNNN: К.ХХ`, где `NNNN` — номер тома, `ХХ` — канал.

Сборка текста в коде (`trubka.be:748-756`): `СРМГ = П'5УСТ С' +
П'РОЧНО ' + код канала (КИН = П'РЧ.К00') + номер тома (Б0000↑)`.

**Вердикт:** `,*50,1206B` в `_s70.mad` — запрос архивной бобины с печатью
`УСТ.СР.К.N БХХХХ` на терминал. К графопостроителю он отношения не имеет.
Графика идёт через подфункции 1205 (`ГРАФИК`, `trubka.be:490-507`) и 1207
(захват БЕНСОНА, `trubka.be:618-632`), а схема НИТИ — через 1210/1216/1217
(`гпнити`, `trubka.be:679-696`). Кадры по 1206 считать нельзя.

## 5. Следствия для Фортран-порта

1. Прямых вызовов KADOP/экстракодов в Фортран-исходниках нет и быть не
   может: это машинные команды/системные вызовы, а не операторы языка.
   Поэтому в порте они вынесены в `fortran/SUPPORT.FTN`
   (`EXC50/EXC70/EXC72/EXC74`).
2. Физический уровень графопостроителя представлен внешними точками входа
   (`PLOT`, `PEN`, `FRAME`, `PAGE`, ...) в `fortran/PLOTSTUB.FTN`.
3. Для удалённого подключения добавлена точка `RPLOT` (заглушка сетевого
   абонента/DKS-моста): она иллюстрирует, что маршрутизация вывода —
   отдельный уровень, не меняющий интерфейс вычислительных подпрограмм.
4. Проверять порт нужно на FOREX 4.12 (`re-forex/tests/plan-f77/t412/
   run-4.12.sh`), а работоспособность драйвера БЕНСОНА — отдельно, на
   эмуляторе с реальной ОС Диспак; в `dispak` ГП заглушён, поэтому
   побайтовая сверка вывода ГП там невозможна.
