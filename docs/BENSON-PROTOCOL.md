# Протокол «БЕНСОН»: что известно после OSINT и локального разбора

Сводка по физическому уровню графопостроителя. Источники: локальные исходники
ДИСПАК, отчёт NASA TM-76182 (сохранён в `reference/`), OSINT по аналогам.
Каждое утверждение помечено как **доказано**, **гипотеза** или **опровергнуто**.

---

## 1. Физическая модель (NASA TM-76182, доказано)

Отчёт описывает подключение «БЕНСОНа» модели 501 (BENSON-FRANCE) к Электронике-1001:

- шаговые двигатели перемещения каретки и пера, перо с подъёмом/опусканием, чернильные перья;
- шесть управляющих линий: `+X`, `-X`, `+Y`, `-Y`, `Pen Control` (подъём/опускание);
- импульс `+5 В` на шине = один шаг; блокировка `Pen Control` на корпус = опущенное перо;
- разъём 11 на боковой стенке;
- интерфейс встроен в систему команд ввода/вывода: первые три значащих бита 12-разрядного слова это код операции (для ГП выбраны `50` и `51`), следующие три, номер устройства, последние три, импульсы УВИ (VV1/VV2/VV3), итого шесть команд.

Таблица 2 отчёта (сверена по изображению страницы 7 PDF, DOS-скан):

| Команда | Код (восьм.) |
|---|---:|
| `+X` | `6502` |
| `-X` | `6514` |
| `+Y` | `6501` |
| `-Y` | `6504` |
| `UP` (перо вверх) | `6511` |
| `DOWN` (перо вниз) | `6512` |

Это современный аналог, а не советский протокол НИТИ напрямую. Использован как
подтверждение физической модели и числа управляющих линий.

## 2. `печшк3`: как получаются 16-разрядные элементы (доказано по коду)

`benson.be:275-282`, подпрограмма `G10236`: из 48-битного слова БЭСМ-6 вырезаются
16-битные группы переменным сдвигом `сда 64(М14)` (счётчик 48→32→16→0, сдвиги
32/16/0) и маской `0177777`.

Основной цикл `G10161` (`benson.be:186-228`):
- `D10115 = 060000` (k=13,14 от младшего) используется как тег;
- управляющее слово `C1 = ((в3 & 060000) << 3) | 01377₈` (источник: `в3`, а не `печшк3`);
- `Q = D10047` (первый элемент), `P = печшк3` (второй элемент).

Маски: `е16п1 = 0177777` (16 бит), `D10310 = 017777` (13 бит нагрузки),
`D10115 = 060000` (2 бита класса), `D10114 = 01377₈` (сервисная константа).
`E_n = 2^(n-1)`, поэтому `E14 = 020000₈`, это бит k=13.

**Разбиение 13 + 2 + 1 подтверждено масками кода:** `017777` (k=0..12) +
`060000` (k=13,14) + `0100000₈` (k=15). 14-й бит (k=13) обрабатывается
отдельно (`benson.be:214-215`: `и E14`, `сда 64+13`); старший бит класса
(k=14) и 16-й бит (k=15) идут парой через `>>14`/`<<16` (`:224-225`).
Отдельных масок `E15`/`E16` в `benson.be` нет.

**Уточнённая поразрядная схема сборки (доказано по коду):**

| k (0 = младший) | Источник |
|---:|---|
| 0 | `Q[13]` (младший бит класса) |
| 1 | 0 |
| 2..14 | `P[0..12]` (13 бит нагрузки второго элемента) |
| 15 | 0 |
| 16 | `Q[14]` (старший бит класса) |
| 17 | `Q[15]` (16-й бит первого элемента) |
| 18..30 | `Q[0..12]` (13 бит нагрузки первого элемента) |
| 31..47 | 0 |

Итоговое слово **не** «два элемента подряд»: старшая 16-битная группа
всегда нулевая, есть биты-заполнители k=1 и k=15. Направления сдвигов проверены
по эталону `besm6_arith.c:450-461`: `сда 64+N` это вправо, `сда 64-N` это влево.

**Гипотеза (по аналогам, не по коду):** семантика битов класса и 16-го бита
(что именно означают пары `060000` и старший разряд). Прямого описания
формата команд Бенсона этого периода не найдено ни в сети, ни в локальных
архивах. NASA-коды `6502/...` сильно отличаются: там один бит выбора
дешифратора и 3-битный one-hot VV, а не 2-битный класс и 13-битная нагрузка.

**Дешифратора команд от Бенсона в ОС НЕТ.** В `benson.be` есть только
программный кодер вывода: `G10236` (`:275-282`) вырезает 16-битные элементы
из 48-битных слов, `G10161/G10175` (`:180-228`) упаковывают их в кольцевой
буфер `ячсост` по адресам `0330..0377`, откуда байты уходят через
`УВВ '164'/'165'` (`:266`, `:270`). Приём данных идёт механически, через
`РЕГ '240'` в `dudka.be:265`: следующая за чтением команда `сбр ЧЕРЕЗ1`
(`:266`) работает с аккумулятором. Ни в одной из этих процедур нет разбора
команды графопостроителя. `simh/BESM6/doc/ГП.md:444` прямо говорит:
«Формат команд не расшифрован; в отличие от РПГ, пошагового кодирования
здесь нет, байты идут на графопостроитель как есть». Любая таблица
декодирования в нашем стенде это гипотеза или `[аналог NASA, БЕНСОН-501]`.

NASA-коды `06502/06514/06501/06504/06511/06512` в нашем стенде помечаются
как `[аналог NASA, БЕНСОН-501]` (`dispak/dispak/extra.c:33`, `:224`, `:234`,
`:314`, `:505-537`). Это аналог для Электроники-1001, а не протокол НИТИ
для БЭСМ-6.

## 3. Кольцевой буфер и побайтовая выдача (доказано по коду)

- Буфер: 40 слов, адреса `0330..0377`, указатель в М13.
- Запись: подпрограмма `G10207`.
- Побайтовая выдача: `G10216`: `и П377` → `нтж П377` (инверсия) → `увв '164'`,
  затем `сда 64+8` и `увв '165'`.
- Готовность: `УВВ '4102'`, разряд E13. Прерывание: ПРП 19 (`УСТПРП Е19`).
- Дополнительное управление: `УВВ '155'` (включение ГП), `УВВ '166'` (состояние),
  `РЕГ '101'/'107'`.

## 4. `D10167` / `D10171`: важная коррекция (опровержение прежней гипотезы)

Ранее по комментарию `dudka.be:324-341` предполагалось, что `D10167` и `D10171`
это команды, подаваемые на Бенсон через `РЕГ '34'` («подтверждение прерывания
и запрос слова» / «запуск передачи»).

Локальный разбор это опровергает:

- `rukava.be:404,536`: `РЕГ '34'` = «ЗАПИСЬ МАСКИ ПРП (МПРП)», дублирует `УВВ '34'`;
- `rukava.be:203`: МПРП это 24-битная маска прерываний;
- разряды констант: `D10167 = в'0000001500000040'` это биты **6, 25, 27, 28**
  (в комментарии `dudka.be:327` ошибочно указан бит 9 вместо 6),
  `D10171 = в'0000001140000000'` это биты **24, 25, 28**;
- прерывание от Бенсона разрешается маской ГРП бит 18 через `ТВ67`
  (`dudka.be:163-165`), а не этими словами.

То есть `D10167`/`D10171` это **маски ПРП/ГРП**, а не команды устройству.
Комментарий в `dudka.be` является ошибочной интерпретацией реконструктора.

Оговорка: в ранней версии `dispak` `РЕГ '34'` был тихим no-op; после добавления
перехвата (`cu.c:790-800`) он вызывает `dudka_reg34_write()`. B1-имитация
воспроизводит приём и учёт этих слов как масок, но не guest-регистры МПРП.

## 5. Аналоги: раскладка битов (OSINT, доказано по аналогам)

| Формат | Раскладка | Источник |
|---|---|---|
| CalComp 565, 6-бит | б0 +X, б1 -X, б2 +Y, б3 -Y, б4 перо вверх, б5 перо вниз | драйвер UvA `gritcalc_e.p` |
| CalComp, лента 570 | триплеты: `7` = +X/+Y/перо вниз, `5` = -X/-Y/перо вверх, `6` = no-action | `aei.pitt.edu/91298/1/3634.pdf` |
| CalComp в ДУБНА | б0 -X, б1 +X, б2 перо вверх, б3 перо вниз, б4 +Y, б5 -Y, б6 no-action | `plotter.cpp` + эталон 2860 байт |
| РПГ ГП1/ГП3 ДИСПАК (УК, 8 бит) | б1 +X, б2 -X, б3 +Y, б4 -Y, б5-6 номер пера, б7 перо поднято, б8 шаг/пера | `simh/BESM6/doc/ГП.md`, `gp4.be` |

Общий формат 16-битных команд именно для Бенсона периода НИТИ не найден.
Найденный Benson 16 Series manual (1986) описывает HPGL/BGL и не относится
к НИТИ/ДУДКЕ.

## 6. Итоговый вердикт

- **Доказано:** физическая модель (шесть линий, шаговые двигатели), алгоритм
  `печшк3` и упаковка 16-битных элементов, кольцевой буфер и побайтовая выдача
  через `увв '164'/'165'`, природа `D10167`/`D10171` как масок ПРП/ГРП,
  схема загрузки ДУДКИ (1216 → КУСГП5 + НОММБ1; зона 0576 = ДУДКА по
  `rukava.be:2733`; отождествление «ГП5 = ДУДКА» остаётся гипотезой).
- **Гипотеза:** структура 16-битного элемента (13+2+1 бит) по аналогам;
  отождествление «ГП5» с ДУДКОЙ.
- **Не доказано:** семантика каждой из девяти «команд» в `РЕГ '34'`
  (это маски, но точное назначение битов 24-28 требует схемы интерфейса);
  формат команд Бенсона на проводе; internal `вдудку` до полного поразрядного
  описания.
- **Опровергнуто:** «D10167/D10171 это команды Бенсону»; «1217 грузит ГП3»;
  «1211 это драйвер НИТИ» (по `rukava.be:600` это CalComp); наличие
  дешифратора команд Бенсона в ОС (дешифратора нет, есть кодер вывода
  `benson.be` и механический приём через `РЕГ '240'`).
