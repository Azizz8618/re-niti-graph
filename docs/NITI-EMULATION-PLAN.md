# План эмуляции графопостроителя по схеме НИТИ в пакетном `dispak`

Цель: проверить работоспособность Фортран-порта библиотеки 22 (ГРАФОР-СУД),
прогнав его в пакетном эмуляторе `dispak` с графопостроителем, подключённым
по схеме НИТИ им. Александрова.

---

## 0. Что уже есть в среде (факты)

| Компонент | Состояние | Источник |
|---|---|---|
| FOREX 4.12 | Работает: `*TRANS:FOREX3*,,411550`, баннер `4.12 OT 25.06.85` | `re-forex/tests/plan-f77/t412/run-4.12.sh` |
| Фортран-порт библиотеки 22 | 238 модулей в `re-niti-graph/fortran/`, компилируется частично (остаточные ошибки) | `fortran/verify/compile-all.sh` |
| ЭК 1211 (вывод на ГП) | В `dispak` уже есть обработчик: 64 слова → файл `plot.dat` в восьмеричных 6-битных группах | `dispak/dispak/extra.c:1700-1727` |
| Схема НИТИ (ЭК 1210/1216/1217, ДУДКА, регистры '34'/'240', прерывания `обвнп1+30`, два буфера `ТБУФ`) | **В `dispak` не эмулируется**; в конфигурации К-71 ГП заглушается `загл7а`/`загл7б` | `re-dispak/AGENTS.md:975-982`; `re-dispak/ai/справочник_ТРУБКА_ДУДКА.md` |
| КАДОПАМ/ДКС | Есть только в SIMH-мосту (`besm6_dks.c` ↔ `pdp11_dks.c`), в C-эмуляторе `dispak` отсутствует | `re-glissade/docs/analysis/dks-bridge-runbook.md` |

Вывод: в `dispak` сегодня есть **только летящий вывод ЭК 1211**. Чтобы проверить
схему НИТИ, нужно либо добавить её обработчики в `dispak`, либо сделать
совместимую прослойку, которая отображает кадры ДУДКИ на уже работающий
`plot.dat`.

## 1. Этап A. Подготовить пакетный прогон порта (без НИТИ)

Цель: убедиться, что порт вообще запускается под FOREX 4.12 в деке.

1. Собрать PERSO-библиотеку из порта:
   - дека по образцу `fortran/verify/run-bytecompare.sh`:
     `DIS 41(2148)^`, `лен 60(2348-wr)^`, `*TRANS:FOREX3*,,411550`,
     исходники `fortran/*.FTN`, `*to perso:602310`;
   - каталог PERSO: не более 12 пользовательских модулей на библиотеку
     (`re-forex/docs/plan-f77/08-runtime.md:135`), поэтому нужны зоны
     `0o2310`, `0o2320`, `0o2330`, ... с картами `*perso:6023NN,cont`;
   - проверить каталог парсером из `re-forex/tests/run-f77-runtime.sh`.
2. Устранить остаточные ошибки трансляции, найденные `compile-all.sh`:
   - псевдо-`ENTRY` (external `SUBP`), `A(*)` (уже заменено на `(1000)`),
     неверные сигнатуры и имена интринзиков;
   - критерий: `ДЛИHA ПOДПPOГPAMMЫ` для каждого модуля, `ЧИCЛO OШИБOK 0000`.
3. Контрольная дека для вызова подпрограмм:
   ```
   шифр 419999 зс5^
   DIS 41(2148)^
   лен 60(2348)^
   еев1а3
   *name NITI01
   *call yesmemory
   *perso:602300
   *perso:602310,cont
   *TRANS:FOREX3*,,411550
         PROGRAM MAIN
   C      вызовы PAGE / MOVE / STRMOD / PLOT из порта
         CALL PAGE()
         END
   *execute
   *end file
   ``````
   еконец
   ```
4. Критерий этапа A: `КОНЕЦ ЗАДАЧИ` без `ОШ`, счётчик `NPLOT` в `/TRACE/`
   (`PLOTSTUB.FTN`) больше нуля, то есть вызов дошёл до физического уровня.

## 2. Этап B. Выбрать модель эмуляции НИТИ

Два варианта. Рекомендуется B2 как быстрый путь к проверке порта.

### B1. Полная аппаратная эмуляция ДУДКИ в `dispak`

Реализовать в `dispak/dispak/extra.c` (или отдельном `niti.c`):

| Что эмулировать | Как | Ожидаемый эффект |
|---|---|---|
| ЭК 1210/1216/1217 | Новый `case` в `extra.c`: принять код подфункции, выставить индекс схемы (М3 − 8 по `trubka.be:679`) | Активация НИТИ |
| Регистр `РЕГ '34'` | Запись 9 управляющих слов БЕНСОНА (`dudka.be:3,319,322`) | Инициализация устройства |
| Регистр `РЕГ '240'` | Чтение слова данных по прерыванию | Поток кадров |
| `УВВ 7` / `ФИЗОБМ` | Перехват физического обмена, разбор КУС с битом 27 (`е27гп`) | Передача кадра в эмулятор |
| Два буфера `ТБУФ` | Таблица адресов `D10161/D10162`, текущий `D10160` | Ping-pong буферов |
| Прерывание `обвнп1+30` (ГРП бит 18) | Поднять бит в ГРП и передать управление по подменённому вектору | Завершение кадра |
| Вывод | Переиспользовать формат `plot.dat` из `extra.c:1700` | Сравнимый эталон |

Плюс: максимальная аутентичность. Минус: заметный объём работы и риск
рассинхронизации с реальной ОС Диспак.

### B2. Функциональная прослойка NITI → ЭК 1211 (рекомендуется)

Не эмулировать регистры и прерывания, а перехватить тот момент, когда
ДУДКА/ТРУБКА передаёт кадр через `ФИЗОБМ` с КУС, содержащим бит 27, и
записать слова буфера в `plot.dat` тем же кодом, что и `extra.c:1700-1727`.
При этом:

- схема НИТИ считается «подключённой», если ЭК 1210/1216/1217 принят;
- каждый принятый кадр = 64 слова = одна строка в `plot.dat` (как сейчас);
- счётчик кадров `D10113` и флаг завершения `D10114` (`dudka.be:239-240`)
  отображаются в diag-вывод эмулятора.

Плюс: минимум изменений в `dispak`, сразу получаем файл, который можно
сравнивать с эталоном. Минус: проверяется поток данных, а не тайминги
прерываний.

## 3. Этап C. Контрольные примеры и критерии приёмки

| Тест | Вход | Ожидаемый результат |
|---|---|---|
| C1. Прямая линия | `MOVE`/`PLOT` между двумя точками | `plot.dat`: 1 кадр, координаты.endpoints |
| C2. Окружность | `CIRC` / `ARCIA` / `CIRTAC` | N кадров, монотонный угол |
| C3. Текст | `SYMBOL`/`NUMBER` | поток 6-битных глифов |
| C4. Страница | `PAGE` / `ENDPG` | завершающий кадр, `КОНЕЦ ЗАДАЧИ` |
| C5. Счётчики | `/TRACE/` в `PLOTSTUB.FTN` | `NPLOT > 0`, `NEXC50/NEXC70` по вызовам |

Дополнительно:

- прогон эталонной декой `re-dispak/testdks/test_k71.txt` (нимити-тест) для
  проверки, что новая прослойка не ломает К-71;
- побайтовая сверка `plot.dat` с эталоном, полученным на original GRAFOR
  (`*LIBRARY:17`, инструкция `krab/doc/sграф`), если эталон доступен;
- фиксация SHA256 `plot.dat` и лога прогона в `.localdocs/` (машинно-локально).

## 4. Этап D. Что делать с расхождениями

1. Если `plot.dat` пуст: проверить, что ЭК 1211/1210 доходит до `extra.c`
   (`set debug=kadopam;...` в SIMH-варианте, `printf`-трасса в `dispak`).
2. Если компиляция порта падает: чинить по одному модулю, начиная с
   `compile-all.sh` (последний прогон: 645 подозрительных строк, часть из них
   ложные срабатывания grep, но `ERR 04052/ERR 01034` реальны).
3. Если кадры идут, но координаты неверны: сверять `COMMON.FTN` с `*GF*`-блоками
   в `madlen/*.mad` (`GFBFTR`, `GFATRN`, `GFBLAN`, `GFGEL`), так как именно
   они несут состояние графопостроителя.

---

## 5. Порядок работ и точки контроля

1. **A1-A2** → порт компилируется без ошибок (LOC: `fortran/verify/compile-all.sh`).
2. **A3** → дека `NITI01` доходит до `PLOTSTUB` (LOC: `PLOTSTUB.FTN`).
3. **B2** → `plot.dat` создаётся при вызове `PLOT` из порта.
4. **C1-C5** → все контрольные примеры проходят, SHA зафиксирован.
5. Только после этого имеет смысл вложить время в B1 (полная эмуляция регистров).

LOC = локальный порядок изменений, не меняет приоритеты: B2 рекомендуется потому,
что даёт проверяемый результат быстрее B1.
