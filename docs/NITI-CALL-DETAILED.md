# Вызов графопостроителя по схеме НИТИ: протокол и тесты

Подробное описание того, как программа БЭСМ-6 добирается до графопостроителя
при **непосредственном (локальном) подключении** по схеме НИТИ им. Александрова,
и как этот путь воспроизведён в нашем стенде на базе `dispak`.

Исходная предпосылка (принятая по указанию): удалённая машина и Э50 133
рассматриваются позже; здесь подключение считается прямым. Разбор удалённого
варианта остаётся в `PHYSICAL-LEVEL.md`, раздел 3.

---

## 1. Участники и общая схема

```
программа (Фортран / МАДЛЕН)
   |  CALL PLOT / CALL PAGE / CALL РАGЕ(...)
   v
библиотека 22 (ГРАФОР-СУД)      <- вычисляет координаты, НЕ управляет пером
   |  общие блоки *GFBFTR*, *GFATRN*, *GFBLAN*, *GFNTCH*, *GFGOBS*
   |  внешние точки входа зоны 0o1163: PLOT, PEN, FRAME, PAGE, ENDPG, ...
   v
системный модуль ТРУБКА         <- принимает экстракоды ГП (1200..1217)
   |  gпнити: выбор схемы НИТИ, ТБУФ, КУС, ФИЗОБМ
   v
драйвер ДУДКА                   <- «БЕНСОН», регистры '34'/'240', прерывания
   |  вдудку, ФИЗОБМ, два буферных листа
   v
графопостроитель БЕНСОН         <- физическое устройство
```

Ключевой факт: **в библиотеке 22 нет кода привода пера**
(`PHYSICAL-LEVEL.md:37-47`). Например, в `MOVE1.mad:37` стоит `PLOT :,SUBP,`
(объявление внешней процедуры), а в `MOVE1.mad:206` вызов `13,VJM,PLOT`.
То есть `PLOT`, контракт с системным драйвером, а не тело в библиотеке.

Связка «ТРУБКА -> ДУДКА -> БЕНСОН» зафиксирована прямо в исходниках:
`benson.be:112-114` «РАБОЧИЙ ВАРИАНТ ТРУБКА->ДУДКА->БЕНСОН»,
`dudka.be:345` `БЕНСОН ВНЕШ БЕНСОН,ошибка,вдудку`,
`benson.be:366` `ВХОД ошибка,вдудку`,
`dudka.be:7-10`: модуль загружается из ТРУБКИ по ЭК 1210 (или 1216/1217)
через `gпнити`.

доказала, что это **не графика**, а запрос архивной бобины с печатью

ЭК 1211 (в реальной ОС, через `ФИЗОБМ`, в нашем эмуляторе, через
обработчик 1211).

Сами точки входа вторичного каталога (`PLOT`, `PEN`, `FRAME` и другие)
дизассемблированы отдельно, итоги находятся в `SECONDARY-CATALOG.md`.

### 2.1. Точный экстракод входа в ДУДКУ: Э50 1210

Правильный код входа в ТРУБКУ и ДУДКУ это **Э50 1210**, а не Э52. Запись
«ЭКСТРАКОДА Э52 1210» в шапке `dudka.be:8` является только комментарием.
В машине код `052` означает COS: `dispak/dispak/cu.c:811-813`
(`case 052: err = elfun(EF_COS)`) и `rukava.be:3050` («Э52 0000 | COS»).
Dispatch подтверждён кодом `vzu.be:2180-2185`:

```
ТРУБ    сч      Е37             , Э50 1210(8) – ГРАФОПОСТРОИТЕЛЬ
        пб      ТВ40            , ВЫЗОВ НЕРЕЗИДЕНТА ТРУБКИ
```

Три разных входа в `гпнити` (коды 1216/1217 отнесены к К-71 в
`rukava.be:3038-3039`):

| Код | Ветка в ТРУБКЕ | Команды перед `пб гпнити` |
|---|---|---|
| 1210 | `.ДА`, `trubka.be:326,335-337` | `СЧ 0; ПБ гпнити` (метка `вхгп2б`) |
| 1216 | `.ДА1`, `trubka.be:351,358-360` | `СЧ E1; ПБ гпнити` (метка `э1216`) |
| 1217 | `.ДА1`, `trubka.be:358-362` | `СЧ 0; ПБ гпнити` (метка `э1217`) |

Коды 1201-1203 и диапазон 1220+ идут через `.ДА2` (`trubka.be:368-380`):
`зп КЛЮЧ; уиа 8(М3); сч ВХ1220; по гпнити; уи М11; пб (М11)`. `ВХ1220`
не является входом в ДУДКУ, это внешняя ячейка ДИСП70
(`trubka.be:797`, `trubka.lst:839` = `00026СА`).

Прямого перехода на ДУДКУ НЕТ. `гпнити` заканчивается `пб ФИЗОБМ`
(`trubka.be:696`), тот же переход повторяется в ветке `нерез`
(`trubka.be:714`), то есть загружается нерезидент с МЛ/МБ. База сохраняется
в `БНСО` (`trubka.be:705`), а ДУДКА стартует `мод БНСО; уиа 0(М16)`
(`dudka.be:54-59`).

Разница двух ветвей после `слиа -8(М3)` (`trubka.be:679`):

- 1210 даёт индекс 0, ветка `пино 0(М3)` (`trubka.be:688`) не срабатывает:
  `или пароль` (`:689`), затем `НОММЛ` и `МАС` (`:692-694`) и `пб ФИЗОБМ`
  (`:696`).
- 1216/1217 дают индексы 6/7, срабатывает `нерез`
  (`trubka.be:687-688,703-714`): `слиа -7(М3)` (`:703`), `зп БНСО` (`:705`),
  `слц п421-ТРУБКА(М7)` (`:707`), `зп трб7яч` (`:708`), таблица трактов
  `заг564`/`гп5` (`:710-717`) и `пб нафиз` (`:714`).

Вывод для стенда: `,*50,1210B` в прослойке `PLOT`
(`verify/native/SHIM.mad:4`, `fortran/verify/PDEV.mad:4`) корректен,
`,*50,1211B` (`SHIM.mad:5`, `PDEV.mad:5`) выдаёт кадр, а коды 1200-1207
кадра не дают: в `dispak/dispak/extra.c:1823-1865` они только логируются
и возвращают `E_SUCCESS`, 1205 печатает `ВК.Г` на терминал (`:1838-1843`),
кадр создаётся только обработчиком 1211 (`:1871-1877`).

### 7.2. B3, мостик от Фортрана к экстракоду

Фортран не может напрямую выдавать экстракоды, поэтому добавлен
`fortran/verify/PDEV.mad`:

```
PDEV: ,NAME,PDEV
      1, VTM,
BUF:  ,BSS,64
      ,*50,1210B
      ,*50,1211B
      13, UJ,
      ,END,
```

`PDEV` собран в PERSO-библиотеку зоны `0o2650` и продублирован в `0o2640`.
В `fortran/PLOTSTUB.FTN` процедура `PLOT()` после инкремента `NPLOT`
вызывает `CALL PDEV()`. Цепочка замкнулась:

```
Fortran CALL PLOT() -> PLOTSTUB (NPLOT++) -> PDEV -> ЭК 1210/1211
                    -> dispak extra.c -> plot.dat
```

PERSO-библиотеки порта занимают зоны `0o2400..0o2650` (22 библиотеки,
не более 12 модулей в каждой). Диск: `fortran/verify/2348-niti.img`,
скрипт пересборки: `fortran/verify/build-niti-disk.sh`.

⚠ В `NITI-EMULATION-PLAN.md:15,84,93` указывается строка `extra.c:1700-1727`
как обработчик 1211; после merge с upstream фактический обработчик находится
в `extra.c:1797-1808`, а запись, в `extra.c:87-108`.

настоящий `ARCIA.FTN` (`0o2400`); так же `SYMBOL` из `XLGAX.FTN` и `NUMBER`
из `INSDEK.FTN`. После удаления псевдонимов и установки координат в
`/GFAFTR/` перед `CALL PLOT()` все тесты прошли.

### 8.3. Родная библиотека 22 с прослойкой точек входа

Чтобы прогнать **родной** DMS-код библиотеки 22, не хватало точек входа
вторичного каталога: `PLOT`, `MOVE`, `RDB`, `ENDPG`, `PAGE`. Они собраны в
МАДЛЕН-прослойке `verify/native/SHIM.mad` и записаны в PERSO зону `0o2700`.
`PLOT` выдаёт ЭК 1210 и 1211, остальные точки возвращаются через `13,UJ,`.

Результат (`verify/native/README.md`, проверено дважды):

```
NITI: scheme 1210 selected
NITI: summary schemes=1 frames=1 words=64 active=1 scheme=1210
 КОНЕЦ ЗАДАЧИ
```

`plot.dat`: 1600 байт, 64 строки, SHA
`15450e0b433bfbc2c2cac11d2528e7a9626f444a0d60b2290c6b325ddff25b2d`.
Нативный вызов `MOVE1(N,X,Y)` + `ARCIA(0.0)` отработал без `ОТСУТСТВУЕТ`
и `E_UNIMP`. Для сравнения, наш Фортран-порт в тесте C1-line даёт 2 кадра,
3200 байт, SHA `181ed477d5a9...`. Разница объясняется разными программами
и координатами, а не несовместимостью протокола.

Отдельно добавлена имитация ЭК 1200-1207 в `dispak/extra.c` (коммит
`a4c177b`): они возвращают `E_SUCCESS` и пишут диагностику, снимая путь
`E_UNIMP`. ЭК 1205 по коду `trubka.be:490-507` не выдаёт кадр, а печатает
`ВК.Г` на терминал, поэтому `plot.dat` по-прежнему создаётся только через 1211.
