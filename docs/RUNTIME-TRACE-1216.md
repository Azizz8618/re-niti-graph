# Трассировка вызова нерезидента ДУДКА на работающем эмуляторе SIMH (БЭСМ-6, ОС ДИСПАК)

Дата: 24.11.2026. Стенд: simh (fork Azizz8618/simh, commit `77739441`),
БЭСМ-6, ОС ДИСПАК с системного диска 2053 (besm6.org, sbor2053.bin).
Проект: `Azizz8618/aesc-crypto-projects` → смежные `re-niti-graph`,
`re-dispak`, `simh`.

## 1. Ответ на главный вопрос

**По какой схеме вызывается нерезидент ДУДКА:**

```
задача (МАДЛЕН, дека *ASSEM)
   |  э50 1216  (экстракод ГП, вариант К-71)
   v
CPU: э50 1200..1237 -> вектор 0550 (ВЗУ, СЕРП)
   v
ВЗУ: ЭКЛИСТ (vzu.be:2139) -> НАЙДУ (2173) -> ТРУБ (2184):
     "сч Е37; пб ТВ40"   - вызов нерезидента Е37 = ТРУБКА
   v
ТВ40 (disp70.be:2236) -> БОЭК1.ВЫЗОВ -> ТИВ -> ШЗН (шкала занятости)
   -> ВИСП15: активация загрузчика нерезидентов ВИСП
   v
ВИСП (visp.be): ТУС-номер нерезидента Е37 -> ТБУФ (лист ОЗУ) -> ВИСП12
   -> ФИЗОБМ: чтение зоны 0413 системного МБ -> ТРУБКА загружена на 10000₈
   v
ТРУБКА (trubka.be:35): точка входа после экстракода
   -> Э5200 (диспетчер, :276) -> пароль СОБР=71717₈ по 19-му слову ИПЗ (М3)
   -> .ДА1 -> э1216 (:358) -> гпнити (:678)
   v
гпнити: слиа -8(М3) => индекс 6; ТБУФ (второй лист);
        пино 0(М3) срабатывает => нерез (:703)
   v
нерез: слиа -7(М3) => 077777₈ (≠0) => пио НЕ срабатывает
        => или кусгп5 (400066₈: сектор 2, тракт 15 программного МБ)
        => или НОММБ1 => пб нафиз => ФИЗОБМ
   v
ФИЗОБМ: чтение зоны 0576 системного МБ (rvs.src:68-70:
        боп1 430576, дудка нс011000 внутри зоны 0576)
   v
ДУДКА (dudka.be:54): мод БНСО; уиа 0(М16) - старт от базы,
        два листа буферов, рег '34'/'240', маска ГРП бит 18 (ТВ67)
   v
БЕНСОН (benson.be:146): вдудку - формирование кадра из зон вывода на МБ
```

**Итоговый ответ: нерезидент ДУДКА вызывается экстракодом Э50 1216**
(«ГП НИТИ, доп. оборудование, вариант К-71»), который через диспетчер
ЭК 50 ОС ДИСПАК загружает нерезидент ТРУБКА (Е37, зона 0413), а уже
ТРУБКА по ветке `э1216 → гпнити → нерез` загружает с программного МБ
(КУС ГП5 = 400066₈) секторный нерезидент ГП5 = ДУДКА (зона 0576).
ЭК 1210 — это вход в ТРУБКУ с загрузкой нерезидента по КУС «пароль»
(4070301400000₈, зона 703 системной МЛ), а не вызов ДУДКА.

Это рантайм-подтверждено для ТРУБКА (зона 0413 читается сразу после
ЭК 1210/1216) и статически доказано для ДУДКА (ветка нерез, rvs.src).

## 2. Что сделано (эксперименты на живом ДИСПАК)

### 2.1. Подготовка стенда

- simh собран из исходников (`make besm6 NOVIDEO=1`, все регрессионные
  тесты PASS, включая gp/gp-irq/gp-fig).
- Диски: 2053 (система), 2048, 2148, 2248, 2063 — с besm6.org; 2348 —
  из репозитория aesc-crypto-projects (том Монитор-80).
- Автоматизация без tmux: pexpect-драйвер консоли эмулятора
  (скрипты `scripts/trace_phase_*.py`).
- Загрузка ОС: RAM-zeroing → `boot_dispak.b6` → `run 2000` → маркер
  `ДATA:`; операторский диалог `ДАЙ А0/А1`, `НОМВ`.
- Ключевой урок: колоду подключать только ПОСЛЕ загрузки ОС
  (`at vu0 <файл>`; `attach -n vu0` в ini обнуляет файл колоды —
  отсюда «ЗМБ0 000000000000» с нулевым шифром в первых прогонах).

### 2.2. Фаза A — все ГП-экстракоды доходят до CPU (4 деки)

Деки `re-niti-graph/verify/niti-lowlevel/t01,t02,t04,t06` поданы на vu0,
console log включал строку `*** TRACE GP-EK050` из `besm6_cpu.c:1521`:

| Дека | ЭК | TRACE-строка (реальная) | Результат задания |
|---|---|---|---|
| t01 | 1210 | `PC=01000 Aex=01210 ACC=0 M3=22731 M16=01000` | B075-1 → КЗ; в листинге АЦПУ «ЗАПРЕЩ.ЭКСТРАКОД» |
| t04 | 1216 | `PC=01000 Aex=01216 ACC=0 M3=22731 M16=01000` | B075-1 → КЗ |
| t06 | 1211 | `PC=01001 Aex=01211 ACC=0 M3=71717 M16=01000` | B075-1 → КЗ |
| t02 | 1210+1211 | `PC=01000 Aex=01210 ACC=0 M3=22731 M16=01000` | B075-1 → КЗ |

Уточнения по сообщениям:
- `B075-1 ШИФР` — штатное «ОС приняла задание» (075 = номер буфера
  ввода), `КЗ(075)` — штатное завершение (ВВОД_АНАЛИЗ.md:889-890).
- `ЗАПРЕЩ.ЭКСТРАКОД` в листинге t01 — авост с кодом 36 (АВРАСП
  «ЗАПРЕЩ.ЭКСТРАКОД» = 36): в t01 не был установлен ключ М3=71717,
  который ТРУБКА проверяет (`НТЖ СОБР`, trubka.be:288). Задания
  завершаются по авосту, но сам экстракод ОС приняла и диспетчеризовала.

### 2.3. Фаза B2 — ЭК 1210 с ключом: ТРУБКА загружается

Дека `t10-key-1210.b6` (ЭК 1210 + `3,VTM,71717B`). Реальная трасса
console log (полный порядок зон ФИЗОБМ):

```
*** TRACE GP-EK050 PC=01001 Aex=01210 ACC=0000000000000000 M3=71717 M16=01000
physobm @17753, zone = 0413, WORD = 10013330573105176   <- ТРУБКА!
physobm @30370, zone = 0677, WORD = 17044001103005176
```

Сразу после экстракода ОС читает зону **0413** — по каталогу модулей
`rvs.src:4` это `трубка … зонгп 430413`. Цепочка
«ЭК → ВЗУ → ТВ40 → БОЭК1 → ВИСП → ФИЗОБМ(зона 0413) → ТРУБКА»
работает в живой ОС. Далее задание ушло в ожидание ГП (цикл 04440 —
холостой цикл ОС), затем ОС остановилась на тупике СТ175 (disp70.be:37):
прерывание ГРП 18Р от БЕНСОНа не приходит, т.к. после 1210 ветка `пароль`
(КУС 4070301400000₈, зона 703 системной МЛ) не загружает ДУДКУ —
обмен с физическим ГП не начат. После СТ175 ОС не принимает новые
колоды (d 5/6 + set cpu req игнорируются).

### 2.4. Фаза C — перезагрузка на деку (не завершена)

Для независимых прогонов 1216+ключ сделана перезагрузка ОС на каждую
деку. Обе попытки упёрлись в обстановочную проблему: на полной скорости
эмуляции (в ini стенда `set throttle=1m` отвергнут: «Non-existent device:
THROTTLE» — throttling в этой сборке не сконфигурирован) команда НОМВ
печатает список задач на АЦПУ0 до готовности принтера, ОС выдаёт
«СБОЙ АЦПУ0» и ждёт директиву «ПОВ А0» (прогон бумаги); pexpect-диалог
успел отработать один раз, во втором прогоне диалог ушёл в таймаут.
Прогон 1216+ключ до трассы зон не доведён — это единственный
недоделанный шаг (см. раздел 4).

## 3. Доказательная база (статическая, по исходникам re-dispak)

Маршрут ЭК 1216 по коду (все номера строк — re-dispak):

1. `vzu.be:2184` — «ТРУБ: сч Е37; пб ТВ40» — Э50 12xx уходит на вызов
   нерезидента Е37 (ТРУБКА). Номер Е37 = бит 37 ТУС, зона 0413
   (`rukava.be:2634`, `rvs.src:4`).
2. `disp70.be:2236` — ТВ40 → БОЭК1.ВЫЗОВ; `disp70.be:2278-2284` — ТИВ:
   занятость в ШЗН; `disp70.be:1256-1286` — ВИСП15 активация ВИСП.
3. `visp.be:45-63` — ВИСП2: номер нерезидента из 36-го слова ИПЗ
   (для ТРУБКА — 12₁₀ = маска Е37); `visp.be:193-203` — ВИСП12: КУС +
   ФИЗОБМ (в прошлом прогоне NATIVE-BLOCKED это давало СМ=6060 в ТБУФ —
   блокер снят, т.к. в наших прогонах зона 0413 реально читается).
4. `trubka.be:35-55` — точка входа ТРУБКА (загружена на 10000₈):
   номер задачи из ИПЗ, М3 := код подфункции из 8-го слова ИПЗ.
5. `trubka.be:276-295` — Э5200: диапазон кода (сда 64+5 → 0), пароль
   `НТЖ СОБР` (СОБР=71717₈, :32), бит 5 → 1201..1217, таблица переходов
   от ЭК1201.
6. `trubka.be:351-362` — `.ДА1` (К-71): `э1216: СЧ E1; пб гпнити`
   (1216 передаёт в ТБУФ режим «дай лист», СМ=1).
7. `trubka.be:678-696` — гпнити: `слиа -8(М3)` → индекс 6 (1216−1200=16₈,
   16₈−8=6); ТБУФ (лист под нерезидент); `пино 0(М3)` — индекс ≠ 0 →
   переход в нерез.
8. `trubka.be:703-714` — нерез: `слиа -7(М3)` → 077777₈ (6−7=−1, ≠ 0) →
   `пио 0(М3)` НЕ срабатывает → **`или кусгп5`** (400066₈: МБ, сектор 2,
   тракт 15) `или НОММБ1` (номер программного МБ) → `пб нафиз` → ФИЗОБМ.
9. `rvs.src:68-70` — зона 0576 системного тома 43: `боп1 … 430576`,
   `есуввк нс010400`, **`дудка нс011000`** — ДУДКА лежит в зоне 0576
   (секторный нерезидент со смещением 011000₈). КУС 400066₈ (сектор 2,
   тракт 15) адресует программный МБ, где размещены нерезиденты ОС
   (rukava.be:2718-2719: «НЕРЕЗИДЕНТЫ ОС ДИСПАК (СООТВЕТСТВУЮТ НОММБ1)»).
10. `dudka.be:54-59` — старт ДУДКА: `мод БНСО; уиа 0(М16)` — база
    сохранена ТРУБКОЙ в БНСО (trubka.be:705); далее два листа буферов,
    инициализация БЕНСОНа через `рег '34'`, маска ГРП бит 18 (`пв ТВ67`,
    dudka.be:163-165), затем `вдудку` в БЕНСОНе (benson.be:146) —
    формирование кадра из зон вывода на МБ.

Различие веток в `гпнити`/`нерез` (арифметика М3 по модулю 2¹⁵):

| ЭК | М3−1200₈ | −8 | −7 | Ветка | КУС | Источник |
|---|---|---|---|---|---|---|
| 1210 | 010₈ | 0 | — | `пино` не срабатывает → `пароль` | 4070301400000₈ | зона 703 системной МЛ |
| **1216** | 016₈ | **6** | **−1** | **`нерез` → `кусгп5`** | **400066₈ + НОММБ1** | **программный МБ → зона 0576, ДУДКА** |
| 1217 | 017₈ | 7 | 0 | `нерез` → `заг564` (`пио` срабатывает) | 4056401400000₈ | зона 0564 (rvs.src:44 — ПЛАН) |

Отождествление ГП5 = ДУДКА: уточнение пользователя зафиксировано в
simh `NATIVE-BLOCKED.md` §13 (коммит 819eecc): «ГП5 и ДУДКА — один и
тот же модуль (кусгп5 = 400066)»; расположение ДУДКА в зоне 0576
подтверждается `rvs.src:70` и `rukava.be:2736` («БОП1, ЕСУВВК, ДУДКА
(НЕРЕЗ. ДЛЯ ГП. НИТИ)»).

Дополнительно: ЭК 50 1216 в привилегированном исполнении (`увв 033`)
в эмуляторе перехватывается хуком `gp_extra` (besm6_gp.c:366-378) —
операции с ячейкой вектора 18Р `обвнп1+30` (04023₈): чтение/запись/
гашение. Это совместимость со стендом dispak; гостевой путь ОС (через
ТРУБКУ) ей не подменяется.

## 4. Что не доведено и почему

1. **Рантайм-трасса зон для ЭК 1216 с ключом** (ожидание: чтение зоны
   0576 с МБ после `гпнити → нерез`) не снята: после ЭК 1210 ОС уходит в
   тупик СТ175 и не принимает следующую колоду, а перезагрузка ОС на
   каждую деку упёрлась в «СБОЙ АЦПУ0» на полной скорости эмуляции
   (throttle в сборке не сконфигурирован; нужно добавить `ПОВ А0` в
   диалог или включить throttling). Точка продолжения: скрипт
   `scripts/trace_phase_c.py`, дека `decks/t16-key-1216.b6`.
2. Брейкпоинт на вход ТРУБКА (br 10000) не срабатывает: ТРУБКА
   исполняется в математическом листе задачи (виртуальная адресация
   через регистры приписки); нужен брейк на физический адрес или трасса
   от TRACE-строки.
3. ДУДКА после загрузки требует обмена с физическим БЕНСОНом
   (рег '34'/'240', прерывание 18Р); в стенде УВВ 0172/0173 и `set gp`
   эмулируются, но кадр по гостевому пути не выведен — задача после
   ЭК 1210+ключ висит в ожидании 18Р.
