# Сравнение родной библиотеки 22 ГРАФОР и Фортран-порта

Методология и текущее состояние A/B-сравнения двух реализаций графического
тракта на БЭСМ-6:

- **родная сторона** - DMS-модули библиотеки 22 (`*library:22`), вызванные
  из Fortran-деки, с МАДЛЕН-прослойкой в PERSO `0o2700`, выдающей кадр через
  ЭК `1210`/`1211`;
- **порт** - Fortran-подпрограммы в свободных PERSO-зонах от `0o2410`, буфер `/PDEVXY/`
  и coords-декодер, кадр тоже идёт через ЭК `1210`/`1211`, но через наш
  мостик `PDEV`.

Обе стороны запускаются через **один и тот же** `dispak` в одном и том же
окружении. Инфраструктура сравнения лежит в
[`verify/native-compare/`](../verify/native-compare/): `run.sh`, `EXPECTED.md`,
`RESULTS.md`.

## 1. Методология

1. Для каждой пары «родная дека / дека порта» раннер ищет родную деку в
   `verify/native-decks/`; пока каталога нет, для `C1-line` используется
   legacy `verify/native/native-final.b6`.
2. На отдельной копии диска 2348 собирается SHIM в PERSO `0o2700`
   (дека `verify/native/shim.b6`), затем прогоняются обе деки.
3. Окружение прогона фиксировано:

   ```
   BESM6_DUDKA_PLOT=benson
   BESM6_DUDKA_TEST=1
   BESM6_DUBNA_PLOT_KEEP=1
   ```

4. Каждая дека прогоняется **дважды**. Собираются `out.txt`, `plot.dat`,
   `benson.out`, `benson.svg`; считаются полные SHA256, размеры, число
   64-словных кадров, число `<path>`, размеры SVG и алфавит команд БЕНСОНа.
5. Сравниваются только инварианты из
   [`EXPECTED.md`](../verify/native-compare/EXPECTED.md): формат кадра,
   алфавит команд, детерминированность, структура SVG, отсутствие ошибок.
6. Родная сторона объявляется готовой только если исключены все маркеры
   «не обновлена»: BSS-only SHIM, `ВЫВОД ЗАПРЕЩЕН`, контрольный SHA
   неинициализированного кадра, нулевые кадры, недетерминированность.

Всё временное - в `/var/tmp`; репозиторий не модифицируется раннером.
Подробные критерии и коды возврата - в `EXPECTED.md`, реальный протокол - в
[`RESULTS.md`](../verify/native-compare/RESULTS.md).

## 3. Что доказывает сравнение, а что нет

**Доказывает:**

- обе реализации доходят до одного и того же тракта эмуляции
  `niti_select()` -> `niti_frame()` -> `niti_plot_write()` и получают
  `plot.dat` в одном формате;
- обе реализации проходят через один и тот же БЕНСОН-кодек и используют
  один и тот же алфавит команд (проверено на C1);
- вывод обеих сторон детерминирован при повторном прогоне на одной сборке;
- родная дека действительно исполняет DMS-код библиотеки 22, а не только
  линкуется с заглушками.

**Не доказывает:**

- совпадение геометрии: родной кадр сейчас берётся из неинициализированного
  `BSS,64`, координаты из `MOVE1` в него не попали;
- корректность масштабирования и отсечения `MOVE1` - для этого нужна
  обновлённая дека A/B, в которой `PLOT` пишет координаты в кадр;
- совпадение с эталоном Дубны или с реальным БЭСМ-6/НИТИ: у тех другой
  тракт декодирования и другой протокол (раздел 4);
- что NASA-коды `065xx` являются настоящими командами НИТИ - они аналог;
- работоспособность полной модели `ФИЗОБМ` с КУС, бит 27: эмулируется
  упрощённый путь через ЭК `1211`, guest `пв ФИЗОБМ` не моделируется.

Отдельно: `ВЫВОД ЗАПРЕЩЕН` - ошибка 25 ДИСПАК (режим запрета перфорации),
а не сообщение графопостроителя. Она появилась из-за отсутствия карты
`ВЫВ ГП 36^` в тестовой деке; это артефакт деки, а не библиотеки или драйвера
ДУДКА. Подробности - [`docs/NATIVE-RUN-ALGORITHM.md`](NATIVE-RUN-ALGORITHM.md).

## 4. OSINT и NASA-оговорки

- NASA TM-76182 (NTRS `19810010147`, локальная копия
  [`reference/NASA-TM-76182.pdf`](reference/NASA-TM-76182.pdf)) описывает
  сопряжение `BENSON-FRANCE 501` с `Электроникой-1001`: пять шин, шаг 0.1 мм,
  шесть 12-битных кодов `6502/6514/6501/6504/6511/6512`. Это **аналог**,
  который в стенде обязан помечаться `[аналог NASA, БЕНСОН-501]`.
- Прямое отождествление этих кодов с протоколом БЭСМ-6/НИТИ опровергнуто;
  proved-путь Дубны с 6 байтами на слово - это `[аналог CalComp]`, а не
  доказанный протокол. См. [`BENSON-PROTOCOL.md`](BENSON-PROTOCOL.md),
  [`BENSON-COMMAND-FORMAT.md`](BENSON-COMMAND-FORMAT.md),
  [`DUBNA-PLOTTER-BRIDGE.md`](DUBNA-PLOTTER-BRIDGE.md).
- OSINT-материалы (NASA-отчёт, CalComp/BENSON-аналоги) использованы только
  как поведенческие свидетельства для физической модели. Ни один защищённый
  код или актив из сторонних источников не скопирован.
- Поэтому эталоном в этом A/B служит не число из Дубны и не таблица NASA,
  а один и тот же бинарник `dispak` с одинаковым окружением. Требовать
  равенства с дубнинскими эталонами было бы подменой предмета сравнения.

## 5. Как запустить

```
cd /home/azizz/Yandex.Disk/re-niti-graph/verify/native-compare
./run.sh                 # все пять пар
./run.sh C1-line         # одна пара
KEEP_WORK=1 VERBOSE=1 ./run.sh
```

Переменные: `DISPAK_BIN`, `DISKDIR`, `REF2148`, `NITI_2348`, `NATIVE_2348`,
`NATIVE_SHIM_B6`, `NC_TMPDIR`, `KEEP_WORK`, `TIMEOUT`, `VERBOSE`.
Код 0 - все пары `СОВМЕСТИМО`, 1 - есть `НЕ ГОТОВО`/`РАСХОЖДЕНИЕ`,
2 - нет обязательного файла, 3 - нет БЕНСОН-бэкенда в бинарнике.
