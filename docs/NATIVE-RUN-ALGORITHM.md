# Алгоритмы прогона: родная библиотека 22 + прослойка вторичного каталога

Разбор того, что именно произошло в прогоне, давшем

```
NITI: scheme 1210 selected
 ВЫВОД ЗАПРЕЩЕН
NITI: summary schemes=1 frames=1 words=64 active=1 scheme=1210
 КОНЕЦ ЗАДАЧИ
```

и `plot.dat` размером 1600 байт. Все пути относительные от `/home/azizz/Yandex.Disk/`.

---

## 1. Что делала дека

`verify/native/native-final.b6`:

```
шифр 419999 зс5^
DIS 41(2148)^        диск 41 = 2148, там живёт FOREX (зона 0o1550)
лен 60(2348)^       диск 60 = рабочая копия 2348 с прослойкой в зоне 0o2700
ееВ1а3
*name NATMA
*call yesmemory
*perso:602700,cont   подключить PERSO-библиотеку зоны 0o2700
*forex               системный FOREX 2.02
      PROGRAM NATMA
      INTEGER N
      REAL X(10), Y(10)
      N = 2
      X(1) = 10.0
      Y(1) = 10.0
      X(2) = 110.0
      Y(2) = 110.0
      CALL MOVE1(N, X, Y)
      CALL ARCIA(0.0)
      END
*library:22          подключить родную библиотеку ГРАФОР-СУД
*execute
*end file
```

То есть Fortran-программа просто готовит два слова точек `(10,10)` и `(110,110)`
и вызывает два **родных** модуля библиотеки 22.

## 2. Почему вообще понадобилась прослойка

Основной каталог библиотеки 22 (зона `0o1100` тома 2048/2348) содержит 238
модулей. Но `PLOT`, `MOVE`, `RDB`, `ENDPG`, `PAGE` в нём **отсутствуют**: это
точки входа **вторичного каталога** в зоне `0o1163`. Fortran-линкер ищет
символы только в загруженных библиотеках, поэтому без прослойки получалось:

```
ОТСУТСТВУЕТ  PAGE
ОТСУТСТВУЕТ  MOVE
ОТСУТСТВУЕТ  RDB
ОТСУТСТВУЕТ  ENDPG
```

Библиотека 12 (`*LIBRARY:12 /ГРАФОР-БАТР./`, зоны 1170-1177) на этих дисках
оказалась не GRAFOR-BATR, а `*JLIB:К71(Z206,С48*71)`, то есть нужных процедур
там нет. Поэтому в PERSO-зону `0o2700` собрана прослойка `SHIM.mad` с пятью
точками входа.

## 3. Алгоритм родного `MOVE1`

Исходник: `madlen/MOVE1.mad` (дизассемблер DMS-модуля с тома 2048).

### 3.1. Точки входа и режимы

```
MOVE1.mad:34  14,VTM,*0002B   первый проход: инициализация буферов
MOVE1.mad:36  14,VTM,*0233B   второй проход: рабочий режим
```

`VTM` загружает в индексный регистр 14 адрес таблицы параметров, дальше идёт
`UJ,*0265B`, переход в общую точку входа. Два прохода нужны, чтобы сначала
подготовить `*GFBLAN*` (состояние пера/отсечения) и `*GFATRN*` (аффинное
преобразование), а затем уже рисовать.

### 3.2. Входные данные через `RDB`

`RDB`, процедура чтения числа пользователя. В `MOVE1.mad` она вызывается
пять раз (`RDB` объявлена `SUBP` в строке 42). Типичный фрагмент:

```
14,VTM,*0302B    подготовить адрес аргумента
,ITA,14          взять его в сумматор
13,VJM,RDB       прочитать число
7,ATX,10B        положить в ячейку 10B
```

То есть координаты приходят не через регистры, а через вызовы `RDB`, которые
читают из массивов `X`, `Y`, переданных в `MOVE1(N,X,Y)`.

### 3.3. Масштабирование и отсечение

Для каждой координаты вызываются `AMAX1` и `AMIN1` (строки 148, 163 и др.):

```
14,VTM,*0307B / 13,VJM,AMAX1 / 7,ATX,11B
14,VTM,*0306B / 13,VJM,AMIN1 / 7,ATX,12B
```

Это задаёт границы **`AMAX1`/`AMIN1` здесь работают как ограничение
снизу/сверху**, формируя границы отсечения из `*GFBLAN*`. Дальше идёт
умножение на масштаб (`7,A*X,16B`) и перевод в целое через `INT`:

```
7,XTA,13B
7,A*X,16B       масштаб
7,ATX,10B
14,VTM,*0306B
13,VJM,INT
7,ATX,11B
```

### 3.4. Выдача кадра

Ключевой момент: в `MOVE1.mad` ровно **одна** выдача на графопостроитель:

```
MOVE1.mad:206   13,VJM,PLOT
```

Все предыдущие ветки (`*0044B`, `*0055B`, `*0104B`, `*0111B`, `*0114B`)
сходятся к `*0114B`, где после расчёта Scaling идёт один вызов `PLOT`.
После него идут запись состояния в `*GFBLAN*` и возврат.

Иными словами, алгоритм `MOVE1`, это «подготовить координаты и один раз
вызвать `PLOT`», а не «вызвать `PLOT` на каждую точку». Это прямо объясняет,
почему в логе `frames=1`, хотя точек было две.

## 4. Алгоритм прослойки `PLOT`

`verify/native/SHIM.mad`:

```
 PLOT: ,NАМЕ,PLOT
 1, VTM,              база модуля в М1
 BUFPL: ,BSS,64       64-словный буфер кадра
 ,*50,1210B           выбрать схему НИТИ
 ,*50,1211B           выдать кадр
 13, UJ,              возврат в вызывающую процедуру
 ,END,
```

Алгоритм:
1. По `VTM` получаем базу модуля (нужна для адресации `BUFPL`).
2. `BSS,64` резервирует 64 слова. Важно: `BSS` **не инициализирует** память,
   поэтому содержимое кадра, то, что там случайно оказалось. Это объясняет
   ненулевые значения в `plot.dat` без начальной инициализации.
3. `ЭК 1210` сообщает dispak, что выбрана схема НИТИ.
4. `ЭК 1211` передаёт адрес буфера; dispak берёт оттуда 64 слова.
5. `13,UJ,` возвращает управление в `MOVE1`.

Остальные точки входа прослойки (`MOVE`, `RDB`, `ENDPG`, `PAGE`) сделаны
проще: `MOVE` вызывает `PLOT` через `13,VJM,PLOT`, остальные сразу
`13,UJ,`. Они нужны только для того, чтобы линкер не выдавал `ОТСУТСТВУЕТ`.

## 5. Алгоритм обработчика в `dispak`

`dispak/dispak/extra.c`, B2-слой.

### 5.1. Выбор схемы `niti_select()` (строки 110-119)

```
niti_active = 1
niti_scheme = code
++niti_schemes
fprintf(stderr, "NITI: scheme %04o selected\n", code)
```

Отсюда в логе `NITI: scheme 1210 selected`, а в сводке `schemes=1`.

### 5.2. Кадр `niti_frame()` (строки 121-134)

```
++niti_frames
niti_words += nwords        (nwords = 64)
niti_plot_write(txt, nwords)
```

Отсюда `frames=1` и `words=64`.

### 5.3. Запись `niti_plot_write()` (строки 87-108)

Для каждого из 64 слов берутся 8 шестибитных полей:

```
for (i = 0; i < nwords; ++i)
    for (j = 7; j >= 0; --j)
        fprintf(plot, "%02o ", (v >> (j*6)) & 077);
    fputc('\n', plot);
```

Одно число `%02o` занимает 3 байта (две цифры + пробел), восемь чисел,
24 байта, плюс перевод строки, **25 байт на строку**.
64 строки × 25 = **1600 байт**. Это точный размер `plot.dat`.

Пример первых строк:

```
64 00 00 00 00 00 00 02
00 00 00 00 00 00 13 56
```

### 5.4. Сводка `niti_report()` через `atexit`

```
NITI: summary schemes=%u frames=%u words=%u active=%d scheme=%04o
```

Печатается при завершении задачи, отсюда последняя строка сводки.

## 6. Почему «ВЫВОД ЗАПРЕЩЕН» и почему кадр только один

`ВЫВОД ЗАПРЕЩЕН`, это **ошибка ДИСПАК номер 25**, а не сообщение
графопостроителя. По `re-dispak/docs/Dispak-programmer-guide.md:8624`:

> `ВЫВОД ЗАПРЕЩЕН`, в задаче установлен режим запрета перфорации.

Текст находится в `re-dispak/avrasp.be:1486` и в таблице ошибок
`besm6-new/besm6-legacy/dispak/errtxt.c:41`. В логе прогона она появляется
между выбором схемы и сводкой, сразу после первого кадра:

```
NITI: scheme 1210 selected
 ВЫВОД ЗАПРЕЩЕН
NITI: summary schemes=1 frames=1 words=64 active=1 scheme=1210
```

То есть после первого `PLOT` система запретила дальнейший вывод. Причина,
в деке нет карты `ВЫВ ГП 36^`, которую каноническое задание из
`krab/doc/sграф` считает обязательной («36, номер абонента сети,
обслуживающего графопостроитель»). Поэтому:

- `MOVE1` успел один раз дойти до `13,VJM,PLOT` и выдать кадр;
- последующий вывод (второй `PLOT` или попытка `ARCIA`) был отклонён;
- `ARCIA(0.0)` с одним аргументом линкуется, но не эмитирует точек, потому
  что общие блоки `*GFBFTR*`/`*GFAFTR*` не инициализированы в этой деке.

Это **артефакт тестовой деки**, а не свойство библиотеки, прослойки или
драйвера ДУДКА (`dudka.be:1-42`). В этом прогоне ДУДКА не загружается:
ЭК 1210/1211 обрабатываются напрямую в `dispak/dispak/extra.c:1866-1877`.
Само сообщение выдаёт ДИСПАК (`re-dispak/avrasp.be:1486`,
`besm6-new/besm6-legacy/dispak/errtxt.c:41`), а не графопостроитель.

## 7. Сравнение с нашим портом C1-line

| | родная библиотека + прослойка | наш порт, C1-line |
|---|---|---|
| Кто считает координаты | нативный `MOVE1` из DMS-модуля | наша Fortran-подпрограмма `MOVE1` |
| Вызов `PLOT` | один, внутри `MOVE1.mad:206` | явно два раза в тексте программы |
| Схема НИТИ | `ЭК 1210` из прослойки `PLOT` | `ЭК 1210` из `PDEV`, вызываемого `PLOTSTUB` |
| Кадр | 64 слова, 1600 байт | 2 × 64 слова, 3200 байт |
| SHA | `15450e0b…` | `181ed477…` |
| Содержимое | из неинициализированного `BSS` | из COMMON `/GFAFTR/` |

Различия объясняются тремя вещами:

1. **Разные программы.** Родная дека вызывает `MOVE1(N,X,Y)`, у которого
   одна точка вывода. Наш C1 явно пишет `CALL MOVE(...)`, `CALL PLOT()`,
   `CALL MOVE(...)`, `CALL PLOT()`, два кадра.
2. **Разные источники координат.** Родной `MOVE1` читает точки через `RDB`
   и преобразует их через `*GFATRN*`/`*GFBLAN*`; наш тест задаёт точки
   константами, а `PLOTSTUB` берёт их из `/GFAFTR/`.
3. **Разный статус вывода.** В родной деке сработал запрет вывода ДИСПАК
   (ошибка 25), в нашей деке карта `ВЫВ ГП` не нужна, потому что кадры
   идут через наш собственный мостик `PDEV`.

Главное: оба пути проходят через одну и ту же точку входа в эмулятор,
`niti_select()` и `niti_frame()`, и дают `plot.dat` в одном и том же
формате. Разница в числе кадров, следствие тестов, а не несовместимости
библиотек.

## 8. Итоговая схема алгоритма

```
Fortran: CALL MOVE1(N,X,Y)
   |
   v
родной DMS-модуль MOVE1:
   RDB (5 раз) -> AMAX1/AMIN1 -> масштаб -> INT -> 13,VJM,PLOT   [один раз]
   |
   v
прослойка PLOT (PERSO 0o2700):
   BUFPL(64) -> ЭК 1210 -> ЭК 1211 -> 13,UJ
   |
   v
dispak extra.c:
   niti_select(1210)  -> schemes=1
   niti_frame(txt,64) -> frames=1, words=64
   niti_plot_write    -> 64 строки × 25 байт = 1600 байт
   atexit(niti_report)-> summary
   |
   v
plot.dat (SHA 15450e0b...)
```

## 9. Оговорки

- Содержимое 64 слов кадра в родном прогоне не является осмысленной
  картинкой: буфер `BSS,64` не инициализирован, а координаты из `MOVE1`
  в эту деку не попали из-за ошибки 25. Тест доказывает работоспособность
  **тракта**, а не корректность геометрии.
- ЭК 1205 (`ГРАФИК`) не участвует: по `trubka.be:490-507` он печатает
  `ВК.Г` на терминал. Кадры идут только через 1211.
- Полная имитация `ФИЗОБМ` с КУС и битом 27 (вариант B1) не реализована;
  наш путь использует расширенный обработчик 1211.
