# Побайтовая сверка порта с оригиналом библиотеки 22

## Что сравнивалось

- **Оригинал:** `madlen/bin/<NAME>.bin` — точные DMS-срезы модулей с тома 2048
  (6 байт на слово, big-endian),те же файлы, которые подавались в `dtran`.
- **Порт:** объектный модуль, который REAL компилятор **FOREX 4.12** получает
  из `fortran/<NAME>.FTN` по команде `*TRANS:FOREX3*,,411550` с записью
  объекта в PERSO-библиотеку зоны `0o2310` тома 2348 (`*to perso:602310`).

Стенд: `run-bytecompare.sh` (копирует диски, строит деку, компилирует,
выгружает объект через `besmtool dump`, вызывает `compare_dms.py`).
Скрипт проверен: баннер `4.12` присутствует, ошибок трансляции нет.

## Результаты (пилот, 4 модуля)

| Модуль | Слов в оригинале | Слов в объекте FOREX | Совпало |Первое расхождение| Вердикт |
|---|---:|---:|---:|---:|---|
| SIZLIN | 28 | 19 | 1/19 (5.3%) | слово 0 | DIFFERENT |
| ABUFF  | 7  | 15 | 2/6  (33.3%) | слово 2 | DIFFERENT |
| DDIST  | 17 | 15 | 1/15 (6.7%) | слово 0 | DIFFERENT |
| COMPDT | 21 | 308| 0/21 (0.0%) | слово 0 | DIFFERENT |

Пример (`SIZLIN`, первое слово заголовка DMS):

```
оригинал: 0000000000040001   head=1 sym=4
FOREX:    0000000000020001   head=1 sym=2
```

Поля заголовка тоже расходятся: у SIZLIN оригинал `cmd=0o22, bss=0o30,
const=0o100`, у объектного модуля FOREX `cmd=0o20, bss=0o40, const=0`.

## Почему побайтовое совпадение невозможно

1. **Разные языки и разные генераторы кода.** Оригинал — рукописный/транслированный
   МАДЛЕН-код с ручной раскладкой индексных регистров М1..М15, модификаторов
   и косвенной адресации `WTC`/`UTC`. Порт — программа на Фортране-77,
   которую FOREX 4.12 компилирует своим алгоритмом распределения памяти
   и регистров. Даже при идентичной семантике машинные слова будут другими.
2. **Разные DMS-шапки.** `sym`, `cmd`, `bss`, `const`, `data`, `long`
   определяются компилятором, а не автором модуля; FOREX выбирает другие
   значения (см. таблицу выше).
3. **Разные соглашения вызова.** МАДЛЕН передаёт аргументы через регистр R14
   и массивы `,EQU,` внутри общих блоков; Фортран передаёт формальные
   аргументы по своей схеме. Компилятор генерирует другой пролог/эпилог.
4. **Экстракоды и физический уровень в порте заменены обёртками**
   (`SUPPORT.FTN`, `PLOTSTUB.FTN`), что дополнительно меняет код.

Побайтовая идентичность была бы достижима только при дословной ассемблерной
реконструкции исходного МАДЛЕН (которого в репозитории нет — есть только
дизассемблированный DMS), либо при искусственной выдаче исходных слов
через `DATA` (что не является портом).

## Что это значит для приёмки порта

Порт нельзя принимать по критерию «байт в байт». Требуется другой критерий —
**функциональная эквивалентность**:

- прогон контрольных примеров GRAFOR (геометрия, масштабирование, подписи)
  и сравнение числовых результатов с заданной точностью;
- сверка вызовов внешних точек входа (`PLOT`, `PEN`, `FRAME`, ...) через
  счётчики в `/TRACE/` в `PLOTSTUB.FTN`;
- прогон на FOREX 4.12 с проверкой отсутствия ошибок трансляции.

Результаты побайтовой сверки сохранены как отрицательный (но воспроизводимый)
доказательный материал: она была выполнена по прямому указанию и показывает,
что перенос на язык высокого уровня не сохраняет машинный код.

## Воспроизведение

```sh
cd re-niti-graph
fortran/verify/run-bytecompare.sh SIZLIN ABUFF DDIST COMPDT
```

Требуется: `dispak`, `besmtool`, диски из `re-forex/tests/plan-f77/t412/`.
