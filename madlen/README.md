# Library 22 (ГРАФОР-СУД) -> MADLEN-style pseudo-assembly

This folder contains a machine-generated disassembly of every **real module** of
BESM-6 system library 22 on volume 2048, produced with the native `dtran`
binary from `re-siprod/dtran`.

**What the `.mad` files are:** MADLEN-style *pseudo-assembly* reconstructed by
`dtran` from compiled DMS object modules. They are **not** the original MADLEN
sources. All source comments and most original identifier spellings are gone;
labels such as `*0005B` are generated by `dtran` from symbol-table/address
information. The output is useful for reading the code and for feeding the
`decomp.pl` decompiler (use `dtran -d` for that preset), not for recovering the
original text verbatim.

## Inputs (read only)

- `../extract/manifest.json` - catalog of 255 records (238 modules + 17
  reference/entry-only records) with zone, word and head-name information.
- `../extract/bin/zone_<decimal>.bin` - 47 zone dumps, each 1024 x 6-byte
  big-endian BESM-6 words, md5-checked against the manifest.
- `/home/azizz/Yandex.Disk/dtran/dtran` - native disassembler. `dtran -h`
  documents all options.

## Reproduce everything

```sh
cd /home/azizz/Yandex.Disk/re-siprod/notes/grafor22-disasm/madlen
python3 slice_and_dtran.py
```

For a single module, the exact command used by the script is:

```sh
/home/azizz/Yandex.Disk/dtran/dtran -F dms bin/COPDCB.bin > COPDCB.mad
```

`-F dms` is required: `dtran` auto-detection needs a non-empty command
section, and some modules have none. If the default fails or produces empty
output, the script tries, in order:

```sh
dtran -F dms -e          <slice.bin>   # expand EQU names to literal values
dtran -F dms -c          <slice.bin>   # render constant references inline
dtran -F dms -R 8        <slice.bin>   # resolve addresses via base register 8
dtran -F dms -D cmdfile  <slice.bin>   # cmdfile contains: code:0
```

The first attempt with exit code 0 and non-empty output wins; every attempt is
recorded in `INDEX.md` and in `dtran_stderr.log`. The `-d` preset (`-e -o -c
-R8`) is *not* used by default because it switches operands to decimal and
changes literal rendering, which makes the output harder to compare with the
octal-addressed listing conventions of the library.

## How a module slice is made

For each `kind == "module"` entry in the manifest, at `word` of its zone the
DMS header is decoded exactly as in `re-siprod/tools/siprod_lib.py`:

```
w0 = head | sym<<12 | debug<<36
w1 = set  | data<<15 | long<<30
w2 = cmd  | bss<<15  | const<<30

disk length = 3 + cmd + const + data + set + head + sym + long + debug
```

The script validates `head == 1` and decodes the single head word (TEXT
encoding) at `word + 3 + cmd + const + data + set`, comparing it with the
catalog name. All 238 modules passed both checks. The byte slice is cut from
the concatenated zone dumps, so modules crossing a zone boundary (35 modules,
up to `ITPLBV` spanning three zones) are complete. The trailing `comment`
section, whose length is not stored in the header, is deliberately excluded.

Filenames: `*` -> `_s`, `/` -> `_p`, other non-alphanumerics -> `_uXX`;
Cyrillic is preserved. The full mapping is in `name_map.tsv`.

## Reading a `.mad` file

Example (`COPDCB.mad`):

```
 COPDCB  :,NAME, NEW DTRAN
C Commands: 14
C Constants: 1
C Memory size: 15
C Actual length of the object file is 22
C Symbol table offset is 20
 ,STI,10
 ,ATI,9
 9,XTA,
 10,ATX,
```

- the first line is the module name banner; `C ...` lines are `dtran`
  comments describing the DMS section lengths;
- lines like ` ,XTA,`, ` 9,XTA,`, ` ,VTM,-5` are MADLEN directives/commands,
  with an optional octal address prefix (`9B`, `*0005B` are label forms);
- constants appear as `,LOG,`, `,INT,`, `,UTC,` etc.; `,END,` closes the module;

## Caveats

- The catalog `load` field is stale for many modules; `INDEX.md` shows both
  the catalog value and `cmd+const+bss` from the header. The header, not the
  catalog, determines the slice length.
- The 17 reference/entry-only records (GETIND, AFTZN, CRDUM, ...) are listed
  at the bottom of `INDEX.md`; they have no module body and were skipped.
- `dtran` writes `Decompiling file ...` / `Format: DMS` to stderr; all such
  diagnostics are collected in `dtran_stderr.log`. All 238 modules succeeded
  with the plain `-F dms` invocation, so no fallbacks were needed.
- No project sources, volume images, or other agents' `extract/` and `disasm/`
  folders are modified by this workflow.

## Files in this folder

- `slice_and_dtran.py` - reproducible generator (this workflow).
- `bin/<name>.bin` - 238 exact DMS module slices, 6 bytes per word.
- `<name>.mad` - 238 dtran outputs.
- `INDEX.md` - per-module table (zone, word, load, disk length, options, size).
- `FAILURES.txt` - dtran failures / header warnings (currently: none).
- `SPOTCHECK.txt` - first 20 lines of three representative outputs.
- `name_map.tsv` - catalog name to filename stem mapping.
- `cmd/<name>.cmd` - `-D` fallback command files (`code:0`).
- `dtran_stderr.log` - all dtran stderr output.
